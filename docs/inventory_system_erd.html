現行DBのER図

現行構造・画面遷移・業務フロー · テーブル定義 · 図面からの設計点検

対象は src-tauri/src/db/migration.rs が登録する現行 schema（v1〜v6）。実店舗DBは参照していない。図は実装の説明であり、業務上の正しさの保証ではない。採用済み仕様と実装が食い違う点は設計点検に分けて記録する。

  • 線は物理FKのみ。点線は非識別関係（子の主キーに親キーを含まない）。端の丸は0を許容し、三つ又は複数を表す。親側が0..1の参照はNULL許容。
  • inventory_movements.reference_type + reference_id と plu_slots.scanning_code = products.jan_code はアプリ側の論理関連で、FKの線を引かない。
  • 数量の非負、JANの有効性、取込み元とsourceの組合せなど、業務条件の全てがDB制約にあるわけではない。通常業務記録の取消・訂正用カラムは未実装。
  • カラムの型・PK/FK・NULL許容・既定値と主要CHECK値を記載。全INDEXのDDLはschema正本を参照。PLUコードのUNIQUEは external / reserved / active に限る部分INDEX。TEXT PRIMARY KEYのNOT NULL未指定もそのまま明記。
  • schema_versions はmigration管理。SQLite内部の sqlite_sequence は図から除く。画像の実体とバックアップファイルはDB外。

関連の全体像

独立して見える表も、業務処理による論理的なつながりを持つ。関連線がないことと、使われていないことは同義ではない。
