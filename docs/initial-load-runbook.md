# 店の PC で本物のデータを入れ始める手順（初期投入、管理者向け）

> **対象**: アプリを管理する人。店の利用者の操作にしない。
> **いつ使うか**: 店の PC にアプリを初めて入れた後（[msi-distribution-runbook.md](msi-distribution-runbook.md) の流れ 2 の後）、業務の入力を始める前に 1 度だけ。
> **引く正本**: 商品 CSV の形は [26](function-design/26-io-product-csv-importer.md) §18.3、取込みの検証と書込みは [30](function-design/30-biz-product-service.md) §4.8・§4.9 と BIZ-01-D5・D6・D8、取込みの画面は [60](function-design/60-ui-product-import.md) UI-01c、部門と独自コードは [master-tables](db-design/master-tables.md) の departments、初期在庫の扱いは [棚卸しの数の置き場の ADR](adr/2026-10-16-stocktake-count-placement.md)（SPEC-STK-CNT-D3・D4）、backup と復元は [68](function-design/68-ui-backup-restore.md) §68.4 と [71](function-design/71-mnt-backup.md)、作り直しの範囲は [decision-log](decision-log.md) D-123。本書は正本の契約を引いて手順を並べ、正本に無い所は安全側に倒した管理者の判断を足す（入れる前の確かめ、予行演習、取り込む前の backup と取込みの後の照合、照合が合わないときの戻し方）。食い違えば正本が正しい。
> **未確認の点**: 実機で確かめていない前提は「未確認（P*n*）」と書き、外れを手順の中の確かめ（[流れ 1](#流れ-1-商品-csv-を作る) の手順 5）か [予行演習](#流れ-2-予行演習) で見つける。

## なぜ 1 度で入れ切るか

- 入れた商品の記録は `product_code` に積もり、商品コードは後から変えられず（master-tables の「独自コードの接頭辞変更」、SP-102-04）、商品は消せない（INV-8）。
- 店の PC への初回の導入をリリースとし、リリースの後は DB を作り直さない（D-123 (5)）。入れた後のやり直しを DB の作り直しで行わない。
- 業務の入力を始める前なら、取り込む直前に作った backup をアプリの復元で戻せば、取り込む前の状態に戻る（[流れ 3](#流れ-3-店の-pc-で入れる) の手順 7）。同じ版で作った backup をアプリの中で戻すだけで、schema も data の folder も変えない。業務の入力を始めた後は、誤りを画面の修正で直す（[入れた後に誤りを見つけたら](#入れた後に誤りを見つけたら)）。

## 流れ 1: 商品 CSV を作る

Excel のある Windows で行う（開発用の PC には Excel が無い。repo 外の回答台帳 TD-437）。在庫 Excel・CSV・backup を repo と開発の folder（repo の checkout）に置かない（[AGENTS.md](../AGENTS.md) の Safety）。

1. 在庫 Excel の写しを別の folder に置き、元の file は変えない。
2. 行を次の種類に分け、種類ごとの数を控える（予行演習と店の PC で同じ数になることを確かめる）。上の行から順に当てはめ、最初に当たった 1 つの種類にする（1 行が 2 つの種類に数えられないので、種類ごとの数の和は在庫 Excel の行の数と同じになる）。「入れない」種類の行は、数を控えた後に表から外す（CSV に書かない）。

   | 行の種類 | 商品コード | JANコード | POS在庫連動 | PLU対象 |
   |---|---|---|---|---|
   | 部門 11（食品）か 12（宅急便）の行 | 入れない（在庫管理の対象外、master-tables の departments） | — | — | — |
   | 在庫 Excel に JAN があるが、店がその JAN を使っていない（レジで読まない。master-tables の布の管理 5 パターンで JAN を「あり（使ってない）」とするパッチワークなど。使っているかは owner が決める） | 独自コード | Excel の JAN（空にしない） | `0` | `0` |
   | 同じ JAN（桁は問わない）を持つ別の商品の群（色違いなど、repo 外の回答台帳 TD-352。master-tables の布の管理 5 パターンの定番ファスナーを含む） | 群の全部の行に独自コード | 群の JAN | `0`（ADR SPEC-STK-CNT-D4。レジの売上で在庫は減らない） | 空 |
   | 13 桁の JAN を持ち、その JAN を他の行が持たない | JAN | JAN（商品コードと同じ値） | 空 | 空 |
   | 8 桁の JAN を持ち、その JAN を他の行が持たない（J4） | 独自コード | 8 桁 | 空 | 空 |
   | JAN もコードも無く、棚卸しの数えから外している長く動いていない品（D-076。どの品かは owner が決める） | 入れない（商品にしない） | — | — | — |
   | JAN もコードも無い（J2。master-tables の布の管理 5 パターンの反物・カット生地を含む） | 独自コード | 空 | 空 | 空 |
   | 上のどれにも当たらない（JAN の桁が 13 でも 8 でもない、部門が決まらない など） | 入れない | — | — | — |

   - JAN は、店がレジで読まない商品でも空にしない（請求書の照合とレジの売上〈Z004〉の参照に使う。レジで読むかは `PLU対象` で分ける。[decision-log](decision-log.md) D-028、master-tables の `plu_target`）。店が JAN を使っていない行の `POS在庫連動` を `0` にするのは、レジで読まないので売上で減らす在庫が無いため。使っているかは JAN ごとに決める（同じ JAN の行は全部この種類になる）ので、在庫連動の商品と同じ JAN を持つ別の商品ができない（30 の共有 JAN の不変条件）。保持した JAN も、プレビューが桁とチェックディジットを見る（J5・TD-426、30 BIZ-01-D10）。
   - `PLU対象` の空は、13 桁の JAN を持つ新しい行を対象にする（上の「今の事実」の PLU対象）。
   - 独自コードは、行の部門の接頭辞（master-tables の初期データ）と、部門ごとに 1 から振る 4 桁の番号で作る（例: 接頭辞 `HZ` の部門の 1 行目は `HZ-0001`）。
   - 独自コードを振る行の部門に接頭辞が無い行が 1 行でもあれば、手順を止める（その行を外して進まない）。部門の初期データを直すのはリリースの前が安い（リリースの後は値のある DB を移す migration が要る。D-123 (4)・(5)）ので、リリースの前に初期データを直す lane を起票する。
   - 「上のどれにも当たらない」行が 1 行でもあれば止め、owner に行の一覧を見せて種類を決める。
3. 列を作る。
   - `売価`: Excel の税抜の売価から `税抜 × (100 + 税率) ÷ 100` を求め、J1 の規則で円の整数にする（例 `=ROUNDDOWN(税抜のセル*(100+税率のセル)/100,0)`。整数を掛けてから 100 で割る。`× 1.1` の形は小数の誤差で、切り上げのときに 1 円ずれる値がある）。
   - `原価`: Excel の税抜の原価を税込に換算せず（D-128）、店の決まり（小数第 3 位で四捨五入して小数第 2 位まで。[共通規則](function-design/10-common-rules.md) SPEC-UNIT-D5 の理由、[35](function-design/35-biz-stocktake-service.md) SPEC-STK-VAL-D3）で丸めた値にする（例 `=IF(税抜原価のセル="","",ROUND(税抜原価のセル,2))`。`ROUND` は空のセルを 0 にするので、空は空のまま残す）。丸めで値が変わった行は手順 4 で一覧にする。
   - `税率`: `10` か `8` か `0`。
   - `部門ID`: master-tables の初期データの部門の番号。
   - `在庫単位`: 商品の数え方の語（[project-memory.md](project-memory.md) の Store Premises Facts の「Counting words differ by category」の行。在庫 Excel の語が数え方と違う区分はその行の下の注記のとおり数え方の語にする）。
   - `初期在庫`: J3 の数。`m` の商品は m の数のまま入れる。
   - `メーカー品番`: Excel にあれば入れる。`取引先ID` は空にする。`PLU対象` は手順 2 の表の値にする。
4. 保存する前に、CSV に書く数字の列（`商品コード`・`JANコード`・`売価`・`原価`・`初期在庫`）を、全部の桁を持つ文字列の値にする。数値のセルは表示のままで書かれ、書式を「文字列」に変えても中の数値は変わらず、先頭の 0 は表示の形でしか持たない（上の「今の事実」の Excel の CSV の保存、未確認 P1）ので、表示の形式に頼らない。表の全部の行を確かめの列で数え（目で抜き取らない。確かめの列の TRUE を `COUNTIF` で数える）、次の順で行う。
   - `売価` か `原価` が 0 の行を、文字列にする前の数の値で一覧にし、予行演習で owner が見る（0 はプレビューが受け付ける）。
   - 手順 3 の丸めで `原価` の値が元の税抜の原価と変わった行（元の原価が小数 3 桁以上）を、同じく一覧にし、予行演習で owner が見る（元の資料の桁の誤りが黙って丸まらないように）。
   - 列ごとに `TEXT` の列を作る。空のセルは空のまま残す（`TEXT` は空を 0 にするので、例 `=IF(セル="","",TEXT(セル,"0.00"))` の形にする）。形式は、`商品コード`・`JANコード` の数字の値が 13 桁なら `"0000000000000"`、8 桁なら `"00000000"`（桁は元の JAN の桁〈商品のバーコードの数字の数〉で選ぶ。手順 2 の 13 桁・8 桁の行はその桁、共有の群と JAN を使っていない行はその行の JAN の桁）、`売価` と個数の単位の `初期在庫` は `"0"`、`原価` と `m` の `初期在庫` は `"0.00"`（取込みは `12.00` を `12` と同じに読む。`parse_hundredths`）。セルを選んだときの上の欄（数式バー）に `4.97638E+12` の類の文字が出るときは桁が既に失われているので、`TEXT` で数字に戻さず元の資料から入れ直す。桁が落ちた・崩れた JAN と指数の形の値は、プレビューが名指しで止める（J5・TD-426、30 BIZ-01-D10。流れ 2 の手順 4）。
   - 置き換える前に、`売価`・`原価`・`初期在庫` の `TEXT` の値が元の値と違う行が 0 であることを数える（確かめの列の例 `=IFERROR(IF(元のセル="",TEXTのセル<>"",IF(TEXTのセル="",TRUE,--TEXTのセル<>--元のセル)),TRUE)`。元のセルが空なら `TEXT` の列も空のときだけ FALSE になる。両辺を数にしてから比べるので、元のセルが文字列で入った数〈`"12.34"`〉でも同じ値なら FALSE になる。どこかでエラーになる行は TRUE になる）。違う行は、`TEXT` が値を丸めた行（丸めた値が CSV に書かれ、プレビューは正常な行として受ける）か、数として読めないセルのある行（元のセルがエラー値や `-`・単位の付いた文字、`TEXT` の列のその行に式が無く空）か、空のセルに `TEXT` が値を書いた行（`IF` の無い `TEXT` の式で `0.00` になった行）。1 行でもあれば、まず数として読めないセルを直し（元の資料から数を入れる、`TEXT` の式をその行まで当てる）、空のセルの行は `TEXT` の式を上の `IF` の形にし、次にその行の形式が上の形式かを見て直す（原価に `"0"` を当てた類の選び違いもここで名指される）。形式が合っていて違う行は、値が列の持てる桁を超えている（`m` の `初期在庫` の小数 3 桁以上〈丸めの決まりが無い〉、`売価` と個数の単位の `初期在庫` の整数でない値）ので止め、owner に行の一覧を見せる。
   - 違う行が 0 になったら、`TEXT` の列の値だけを貼り付けて元の列と置き換える。
   - 数字だけの `商品コード` が `JANコード` と同じでない行が 0（手順 2 の表では、数字だけの商品コードは JAN を商品コードにした行だけで、`JANコード` に同じ値を持つ。確かめの列の例 `=AND(ISNUMBER(--商品コードのセル),商品コードのセル<>JANコードのセル)`）。1 行でもあれば、その行を filter で出して手順 2 の表のとおりに直す。
   - `JANコード` が 13 桁で `00000` から始まる行が 0（8 桁の JAN に 13 桁の形式を当てた値。チェックディジットが合ってしまい、プレビューは止めない。確かめの列の例 `=AND(LEN(JANコードのセル)=13,LEFT(JANコードのセル,5)="00000")`）。1 行でもあれば、その行を手順 2 の 8 桁の JAN の行（共有の群か JAN を使っていない行なら、その種類のまま 8 桁の JAN）として直す。13 桁の JAN の行に入れて商品コードも `00000…` にしていたら、J4 のとおり商品コードも決め直し（J4 の既定 b なら独自コード）、手順 2 の種類ごとの数を数え直す。
   - 指数の形の値の行、13 桁の数字の `商品コード` で `JANコード` が空の行、`JANコード` の桁かチェックディジットが合わない行、`商品コード` の重複と上限を超える値は、プレビューが行の error にする（J5・TD-426、30 BIZ-01-D10・BIZ-01-D5。流れ 2 の手順 4）ので、ここでは数えない。
5. CSV にする sheet の形を整える: 1 行目を列名（上の「今の事実」の列の行の名）にし、同じ名の列を置かない（取込みは同じ名の列の後ろの値を取る。`parse_product_csv`）。作業の列、確かめの列と数えたセルは消す（CSV に保存されるのは開いている sheet だけで、その上のセルは全部書かれる）。「CSV UTF-8（コンマ区切り）」として保存する（BOM 付きの UTF-8。取込みは先頭の BOM で UTF-8 として読む〈26 §18.3、`decode_bytes`〉。「CSV（コンマ区切り）」は CP932 で書き、CP932 に無い文字を黙って `?` に替える見込みなので使わない。未確認 P1）。保存した file を Excel で開いて上書き保存しない（数字の列が数値に戻り、指数の形で書き直される見込み）。
   - 保存した file の中身を、取り込む前に全部の行で確かめる（Excel が文字列のセルを中の文字のまま書くかは確かめていない〈未確認 P1〉ので、保存の振舞いに頼らず、取り込む file そのものを見る）。PowerShell に下を貼り、`$f` に file の path（`C:\` から始まる全体の path）を入れて実行する。最初に file の先頭の 3 byte が UTF-8 の BOM（`EF BB BF`）かを見て、違えば保存し直しを名指す 1 行だけを出して止まり、行を読まない（アプリは先頭の 3 byte が BOM なら UTF-8、それ以外は CP932 として読む〈上の「今の事実」の文字コード、`decode_bytes`〉ので、BOM があれば下の読み方とアプリの読み方が同じになる）。BOM があれば、5 つの数字の列が手順 4 で決めた形（`商品コード` は 13 桁か 8 桁の数字か独自コード、`JANコード` は空か 13 桁か 8 桁の数字、`売価` は整数、`原価` は小数 2 桁、`初期在庫` は `m` の行で空か小数 2 桁、ほかの行で空か整数）でない行を、行の番号・列・file に書かれた値で出し、最後に確かめた行の数を出す。

     ```powershell
     $f = 'C:\…\商品.csv'
     $b = [System.IO.File]::ReadAllBytes($f)
     if ($b.Length -lt 3 -or $b[0] -ne 0xEF -or $b[1] -ne 0xBB -or $b[2] -ne 0xBF) {
       '止める: 先頭に UTF-8 の BOM が無い。「CSV UTF-8（コンマ区切り）」で保存し直す'
     } else {
       $n = 1
       Import-Csv -LiteralPath $f -Encoding UTF8 | ForEach-Object {
         $n++
         $r = $_
         $s = if ($r.'在庫単位' -ceq 'm') { '^([0-9]+\.[0-9]{2})?$' } else { '^[0-9]*$' }
         $bad = @(
           if ($r.'商品コード' -cnotmatch '^([0-9]{13}|[0-9]{8}|[A-Z]{2}-[0-9]{4,})$') { '商品コード' }
           if ($r.'JANコード' -cnotmatch '^([0-9]{13}|[0-9]{8})?$') { 'JANコード' }
           if ($r.'売価' -cnotmatch '^[0-9]+$') { '売価' }
           if ($r.'原価' -cnotmatch '^[0-9]+\.[0-9]{2}$') { '原価' }
           if ($r.'初期在庫' -cnotmatch $s) { '初期在庫' }
         )
         if ($bad) { "$n 行目: " + (($bad | ForEach-Object { "$_=[$($r.$_)]" }) -join ' ') }
       }
       "確かめた行の数: $($n - 1)"
     }
     ```

     「止める: 先頭に UTF-8 の BOM が無い」が出たら取り込まず、手順 5 の保存の種類を「CSV UTF-8（コンマ区切り）」にして保存し直し、もう一度この確かめを回す（「CSV（コンマ区切り）」〈CP932〉や BOM の無い UTF-8・UTF-16 の file はここで止まる。アプリは BOM の無い file を必ず CP932 として読み、この手順書は CP932 を使わないので、アプリより厳しく止める）。BOM があっても中身が UTF-8 として正しくない file は、流れ 2 の手順 4 の取込みが file の error（「Excelで保存し直してください」）で止める。出力が「確かめた行の数」の 1 行だけで、その数が手順 2 の種類ごとの数の和（入れない行を除く）と同じなら進む。行が出たら取り込まず、出た行の sheet のセルを見る。出た行が全部の列が空の行（sheet の下に残った空の行。`商品コード`・`売価`・`原価` が `[]` で出る）なら、CSV にする前の sheet の、全部の列が空の行を行ごと消し、手順 5 の保存からやり直す（保存した file を Excel で開いて上書きしない）。確かめた行の数が手順 2 の和より空の行の数だけ多い（1 ずれる類）のも同じ原因で、下の「sheet のセルが手順 4 の形なのに file の値が違う」には当たらない。sheet のセルが手順 4 の形でないなら、列で直し方が分かれる: `商品コード` の誤り（手で振った独自コードが `HZ-001`・`HZ0001` の類で `接頭辞-4 桁以上の番号` の形でない）は手順 2 の表と箇条のとおりに直す。負の値（`-5.00` の類）と空の原価は、元の資料から値を入れ直して手順 3 の列を作る段からやり直す。数値のまま残ったセル・`TEXT` の当て忘れ・形式の選び違いは、その列を手順 4 の `TEXT` の列を作る段からやり直す。どれも、直した段から順に手順 5 の保存と確かめまで進め直す（手順 3 から直した行も、手順 4 の丸めで変わった行の一覧と比べの列を通す）。sheet のセルが手順 4 の形なのに file の値が違うなら、Excel の保存がセルの文字を書き替えた（P1 が外れた）ので、この手順書の保存の段では入れられない。出た行と値を管理者の記録に控えて止め、保存の段を直す lane を起票する。数が手順 2 の和と違えば、sheet の行を見て直す。値の中の改行は、プレビューの行の error で名指される。取り込む前に止まる（sheet のそのセルの改行を消し、手順 5 の保存からやり直す）。
   - file の SHA-256 を `Get-FileHash` で取り、管理者の記録（repo の外）に書く。

## 流れ 2: 予行演習

店の PC に入れる前に、店の PC へ入れる版（初回の導入の版。[Plans の導入の前の関門](Plans.md#導入の前の関門) の confirmed の項目を全部満たした版）の MSI を開発用の Windows に入れ、流れ 1 の CSV（開発用の Windows へ写し、SHA-256 が管理者の記録と同じことを確かめた file）で同じ手順を通す。MSI の予行演習（[msi-distribution-runbook.md](msi-distribution-runbook.md) の確かめる項目の M1〜M8）は 2026-10-24 に済んでいる。同じ日に MSI の試験（試験用のデータを入れるもの）も行うときは、それを終えて msi-distribution-runbook.md の「予行演習の準備と片付け」の「終わった後」まで済ませてから、下の手順 1 から始める（試験用のデータの DB に CSV を入れない。店のデータの DB に試験用のデータを入れない）。

手順 3〜7 は同じ日に続けて行う。その日のうちに手順 7 まで終えられなければ、手順 7 と同じく手順 3 の backup へ復元して商品が 0 件に戻ったことを確かめてから閉じ、次の回は手順 3 から始める（取り込む前の backup は保存先の中で作った日のうちは消えないが、日をまたぐと起動の時の保持日数の削除で消えうる。上の「今の事実」の backup の保持。流れ 3 も同じ）。

1. msi-distribution-runbook.md の「予行演習の準備と片付け」の「始める前に」のとおり、開発のデータの folder を退避する。
2. 店の PC へ入れる版の MSI を入れて起動し、ホームが出ること、商品が 0 件であることを確かめる（作業フォルダーの `inventory.db` の確かめも同じ準備の段のとおり）。商品が 1 件でもあれば止める。商品の登録の画面の部門の一覧を owner が見て、今のレジの部門と合うことを確かめる。合わなければ止める（部門は初期データで、直すのはリリースの前に初期データを直す lane。D-123 (4)・(5)）。
3. 「バックアップ・復元」で手動バックアップを作る（取り込む前の backup）。
4. 「一括インポート」で CSV を選ぶ。プレビューの新規登録候補の数が流れ 1 の手順 2 の数の和（入れない行を除く）と同じで、エラー行と重複行が 0 であることを確かめる。file の error（文字コードが判別できない、必須の列が不足している）が出たら、流れ 1 の手順 5 からやり直す（必須の列の不足は、sheet の 1 行目の列名が上の「今の事実」の列の行の名と違うか、列が足りない。列名を直してから保存と確かめを回す）。エラー行があれば取り込まず、プレビューが名指した行と直し方のとおりに CSV を直して流れ 1 の手順 3 からやり直す（プレビューは DB を変えない。指数の形の値の行、13 桁の数字の `商品コード` で `JANコード` が空の行、`JANコード` の桁かチェックディジットが合わない行も、ここで全件が名指される。J5・TD-426、30 BIZ-01-D10。名指された JAN は元の資料〈商品のバーコードの数字〉から入れ直し、元の資料でも合わなければ止めて owner に行の一覧を見せる）。
5. 取り込む。完了の画面の新規登録の数がプレビューの新規登録候補の数と同じであることを確かめる。
6. 照合する（流れ 3 の手順 6 と同じ項目。元の在庫 Excel を開ける PC〈Excel のある Windows〉を手元に置く）: 行の種類ごとに数件を選び、商品の画面で商品コード・商品名・JAN・部門・単位・在庫の数・原価を見る。在庫の数は、流れ 1 の手順 3 で値を取った元のセル（元の在庫 Excel は手順 1 で変えずに残した file）の数式バーに出る値と比べ、原価は同じ元のセルの値を同じ店の決まり（流れ 1 の手順 3 の丸め）で丸めた値と比べる（セルの表示と比べると、表示の桁で丸まった値が入っていても合ってしまう）。ほかの項目は流れ 1 の手順 5 で確かめた CSV の値と比べる（CSV はメモ帳か、PowerShell で `$f` に開発用の Windows へ写した CSV の path を入れてから〈例 `$f = 'C:\…\商品.csv'`〉`Import-Csv -LiteralPath $f -Encoding UTF8 | Out-GridView` で見る。Excel で開かない〈数字の列が数値の表示に戻り、閉じるときの保存の確認で上書きしうる。流れ 1 の手順 5〉）。原価に小数のある商品と `m` の商品を必ず含める。売価は店の値札と比べる（J1。税込にすると端数の出る売価の商品を必ず含める）。`m` の商品の在庫が m で合うこと、同じ JAN の群と JAN を使っていない行が在庫連動でないこと、JAN を使っていない行が JAN を持ってレジの書出しの対象外であることを見る。整合性の検証の画面で不整合が出ないことを見る（[75](function-design/75-ui-integrity-check.md)）。流れ 1 の手順 4 の 0 の行と丸めで原価が変わった行の一覧を owner が見る。
7. 取り込む前の backup を「バックアップ・復元」の一覧から選んで復元し、商品が 0 件に戻ることを確かめる（流れ 3 の手順 7 の戻し方を 1 度通す。復元で商品と入出庫の記録が 0 件に戻ることは code の上で確かめた〈P2〉。ここでは画面の上で確かめる）。
8. 片付けは msi-distribution-runbook.md の「予行演習の準備と片付け」の「終わった後」のとおり。予行演習で出来た folder には店のデータが入るので、消す時期は owner が決める（71 §71.13 の別の PC に店のデータを置く間の扱いと同じ）。

全部が合ったときだけ流れ 3 へ進む。1 つでも合わなければ、合わなかった項目を控え、CSV か手順を直して流れ 1 からやり直す。

## 流れ 3: 店の PC で入れる

前提: msi-distribution-runbook.md の流れ 2 が済み（アプリが起動し、商品が 0 件で、手動バックアップが 1 つある）、予行演習を同じ版の MSI と同じ CSV（SHA-256 が同じ）で通している。業務の入力をまだ始めていない。

手順 2〜7 は同じ日に続けて行う。その日のうちに手順 6 の照合と手順 7 の判断を終えられなければ、業務の入力を始めずに手順 7 と同じく手順 2 の backup へ復元してから閉じ、次の回は手順 2 から始める（取り込む前の backup は保存先の中で作った日のうちは消えないが、日をまたぐと保持日数で消えうる。上の「今の事実」の backup の保持）。

1. CSV を店の PC へ写し、SHA-256 が管理者の記録と同じことを確かめる。違えば入れない。
2. 「バックアップ・復元」で保存先を確かめ、手動バックアップを作る（取り込む前の backup）。出来た file を、保存先の外の日付の付いた folder と PC の外の媒体の 2 か所へ写し、SHA-256 が同じことを確かめる（保存先の中は保持日数を過ぎると消える、71 §71.5）。どれかが失敗したら取り込まない。
3. 「一括インポート」で CSV を選び、プレビューの数が予行演習と同じで、エラー行と重複行が 0 であることを確かめる。違えば取り込まずに止める。
4. 取り込み、完了の画面の数を確かめる。
5. アプリを閉じて開き直し、ホームが出ることを確かめる。
6. 予行演習の手順 6 と同じ項目で照合する。
7. **全部が合ったときだけ業務の入力を始める。** 1 つでも合わなければ業務の入力を始めず、合わなかった項目を控え、手順 2 の backup を「バックアップ・復元」の一覧から選んで復元する（戻す前の自動の backup は取込みの後の状態として残る）。商品が 0 件に戻ったことを確かめ、CSV を直して流れ 1 から（予行演習を含めて）やり直す。
8. 設定を確かめる: 自動バックアップが有効で、保存先が意図した folder であること。PC の外の控えの USB メモリを用意する（68 §68.4 の「PC の外の控え」。D-114 の runtime を含む版で。導入の前の関門の 3）。
9. 手動バックアップを作り、手順 2 と同じく 2 か所へ写す（最初の backup）。管理者の記録に、アプリの版・CSV の SHA-256・行の種類ごとの数・初期在庫の数を数えた日（J3）・最初の backup の file 名と SHA-256 を書く。

## 入れた後に誤りを見つけたら

業務の入力を始めた後は、取り込む前の backup へ戻さない（戻すと、その後の入力が消える）。

| 誤り | 直し方 |
|---|---|
| 商品名・部門・売価・原価・税率・メーカー品番・在庫連動 | 商品の修正の画面か、CSV の上書き（重複行で「上書き」を選ぶ。60 UI-01c-D6・D7）。上書きの CSV には、今の `JANコード` を全部の行に入れる（`JANコード` が空か列が無い上書きの行は JAN を消す。上の「今の事実」の上書きの JANコード） |
| JAN | CSV の上書き（商品の修正の画面では JAN を読むだけ。[SCREEN_DESIGN.md](SCREEN_DESIGN.md) の商品フォーム）。新しい JAN は 8 桁か 13 桁でチェックディジットの合う値にする（プレビューは上書きの行も新規の行と同じく検査する。TD-426、30 BIZ-01-D10）。13 桁の JAN を入れ直すときは、`PLU対象` を、その商品をレジで読むなら `1`、読まないなら `0` にする（上書きの行で空だと今の値を保つ。上の「今の事実」の PLU対象）。レジで読まなくなっただけの商品は、JAN を消さず `PLU対象` を `0` にする（D-028）。この直しでは `POS在庫連動` を空にして今の値を保つ（変えるときは上の在庫連動の行で直す）。JAN が誤りで消すときは、その行の `JANコード` を空にする。ただし商品コードが 13 桁の数字（JAN を商品コードにした商品）の JAN は消せない（その行はプレビューが止める。J5。JAN を消したい理由はその JAN を商品コードにしたこと自体の誤りなので、下の商品コードの行と同じく止めて owner に諮る） |
| 単位（個数の単位どうし） | 商品の修正の画面で直す（D-119） |
| 単位（個数と長さをまたぐ）・商品コード | アプリの中では直せない（30 BIZ-01-D8 の上書きの単位、SP-102-04）。止めて owner に諮る。廃番にして別のコードで登録し直すと、JAN を商品コードにした商品では同じ JAN の商品が 2 つになる（ADR SPEC-STK-CNT-D4 の在庫連動の外になる）ので、予行演習で見つけて入れる前に直す |
| 在庫の数 | 棚卸しの計数で直す（D-118。計数の保存は (b)。入出庫と初期在庫の記録は書き換えない） |
