## IO-08: EJパーサー

文書名は `29-io-ej-parser.md`。同じ CASIO SR-S4000 adapter の日報 parser（[29-io-daily-report-parser.md](29-io-daily-report-parser.md)）と番号 29 を共有するため、参照は常に file 名全体で書く。節番号は `IO-08.1`〜`IO-08.10` とし、Spec Contract IO-08-D1〜D10 に 1 対 1 で対応させる（日報 parser の `§29.n` とは別の系列）。節の中の子の決定は `IO-08-D3a` のように親の番号に英字を付ける（全期間の EJ に合わせた文法の追加、[decision-log](../decision-log.md) D-105）。

### 目的

`ej_parser` は、店のレジ（CASIO SR-S4000）が売上/EJ 保存設定で SD に書く電子ジャーナル（EJ）1 file の生バイト列を、記録（取引・取引中止・入金 / 出金 / 替・領収書・精算票・点検票・設定・練習）の列へ構造復元する純関数モジュールである。記録の種類は見出しのモード欄ではなく本文の行で決める（IO-08-D3a）。通常販売と返品の取引は、本書の文法に一致し記録内の照合がそろう場合に限り、明細（印字名称・数量・単価・金額）と値引きへ復元する。一致しない記録は、その記録だけを「復元不能」として返し、明細を読み出せない型にする。どの行も黙って捨てない。

この層は CASIO 固有の固定幅・ラベル・モード欄を吸収する。番号の連続・区間の完全性・商品の同定・時刻の解釈は行わない（IO-08.9）。出力型（記録・明細・復元状態・診断）は後続の BIZ が使う core 側の契約で、レジが替わった場合は `ej_parser.rs` と本書を取り替え、出力型を保つ（D-023）。

### モジュール構成

```
src-tauri/src/io/
└── ej_parser.rs   # parse_ej と出力型。合成 fixture の unit test と実物確認用の ignore 付き test を同じ file に置く
```

`parse_ej` 以外の `pub fn` を置かない。

### 型定義

```rust
pub struct EjParseResult {
    pub file_hash: String,            // 生バイトの SHA-256（小文字 hex 64 文字）
    pub leading_lines: Vec<EjLine>,   // 最初の記録ヘッダより前の行（IO-08.4）
    pub records: Vec<EjRecord>,       // file の出現順
    pub diagnostics: Vec<EjDiagnostic>,
}

pub struct EjLine {
    pub line_no: usize,   // 1 始まり
    pub text: String,     // decode したままの行（空白を除去しない）
    pub kind: EjLineKind,
}

pub enum EjLineKind {
    Separator,
    Quantity { quantity: i64, unit_price: i64 },
    Item { name: String, amount: i64 },       // 金額は印字の符号のまま（戻の印の直後だけ負）
    ItemName { name: String },                // 折り返した明細の名称の行（IO-08-D5a）
    Continued { amount: i64 },                // 直前の行の続きの金額だけの行（IO-08-D5a）
    ItemCount { count: i64 },                 // 符号つき
    Labeled { label: &'static str },          // prefix だけで判定。値は解釈しない
    Correction { amount: i64 },               // 訂正（IO-08-D6a）
    Subtotal { amount: i64 },                 // 小計
    DiscountRate,                             // 率の行（`-N%`）。値を解釈しない
    PercentDiscount { amount: i64, subtotal: bool },   // ％値引き。subtotal = 金額の後に `*`
    MinusKey { amount: i64 },                 // マイナスキー（`－`）
    ReturnMark,                               // 戻の印（`戻 ････`）
    CancelMark,                               // 取引中止の印（`取引中止 ････`）
    NumberPrint,                              // 番号印字（`＃ N`）。値を解釈しない
    ReportTitle { leading_no: Option<String>, trailing_no: Option<String> },
    ReportEnd,
    AmountOnly,
    Text,                                     // 値を解釈しない文字の行（案内文・設定の印字・練習の本文）
    Status { label: &'static str, result: String },
    Unknown,
}

pub struct EjRecord {
    pub header_line_no: usize,   // ヘッダ 1 行目の行番号。2 行目は header_line_no + 1
    pub mode: EjMode,            // 見出しのモード欄。記録の種類は kind（IO-08-D3a）
    pub kind: EjRecordKind,
    pub printed_at: String,      // `YYYY-MM-DD HH:MM`。変換しない
    pub number_prefix: String,   // 番号行の 4 桁の欄。意味は未検証
    pub number: String,          // 番号行の 6 桁の番号。先頭 0 を保つ
    pub body: Vec<EjLine>,       // ヘッダ 2 行を除く本文（常に保持）
    pub restoration: EjRestoration,
}

pub enum EjMode {
    Normal, Return, Training, Settlement, Inspection,
    Program, Program1, Program3, Off, Unrecognized(String),
}

pub enum EjRecordKind {
    Sale,                                                     // 取引（区切りあり）
    Cancelled,                                                // 取引中止
    CashMovement,                                             // 入金 / 出金 / 替
    Receipt,                                                  // 領収書の発行
    Settlement { report: EjSettlementReport, completed: bool },   // 精算票（Z）
    Inspection,                                               // 点検票（X）
    Settings,                                                 // 設定の書込み・読込み・保存・印字
    Training,                                                 // 練習
    Unclassified,                                             // どれにも当たらない（常に Unresolved）
}

pub enum EjSettlementReport { Daily, Plu, Attendance }   // 日計明細 / ＰＬＵ / 勤怠

pub enum EjRestoration {
    Restored { items: Vec<EjItem>, item_count: i64, adjustments: Vec<EjAdjustment> },
    NoItems,
    Unresolved { reasons: Vec<EjDiagnosticCode> },   // 明細の field を持たない
}

pub struct EjItem {
    pub line_no: usize,            // 名称行の行番号（折返しは名称だけの行）
    pub name: String,              // 印字名称（末尾の空白を除く）
    pub quantity: i64,             // 数量行が掛かる明細はその値、戻の印の明細は -1、それ以外は 1
    pub unit_price: Option<i64>,   // 数量行があるときだけ Some
    pub amount: i64,               // 円。印字の符号のまま。返品モードでも符号を反転しない
}

pub struct EjAdjustment {
    pub line_no: usize,            // ％値引き・マイナスキーの行の行番号
    pub kind: EjAdjustmentKind,
    pub amount: i64,               // 円。印字の符号のまま（負）
}

pub enum EjAdjustmentKind {
    ItemDiscount { item_line_no: usize },   // 明細値引き。直前の明細の line_no
    SubtotalDiscount,                       // 小計値引き
    MinusKey,                               // マイナスキー。掛かり先を解釈しない
}

pub struct EjDiagnostic {
    pub line_no: Option<usize>,    // 範囲 File のときは None
    pub code: EjDiagnosticCode,
    pub scope: EjDiagnosticScope,
    pub message: &'static str,     // code ごとの固定文言（IO-08.8）
}

pub enum EjDiagnosticCode {
    UnknownLine, InvalidWidth, UnrecognizedMode, InconsistentRecord,
    IncompleteRecord, MissingFinalNewline, LeadingFragment,
}

pub enum EjDiagnosticScope { Line, Record, File }

pub enum EjParseError {
    DecodeFailed(String),
    NoRecords(String),
    Empty(String),
}
```

`EjDiagnostic.message` を `&'static str` にするのは、文言が code ごとの固定文言だけであることを型で保つためである（行の生の文字列を後から埋め込めない）。

### IO-08.1 入力と致命的エラー（IO-08-D1）

**関数要求**: EJ 1 file の生バイト列を受け取り、記録の列・先頭断片・診断と file_hash を返す。後続の BIZ（区間の照合・商品同定・在庫反映）と訪店時の実物確認が、同じ関数で「この取引の明細は確かか」を判定できるようにする。

**シグネチャ**:

```rust
pub fn parse_ej(raw_bytes: &[u8]) -> Result<EjParseResult, EjParseError>
```

**前提条件**: 純関数。DB 非依存・副作用なし。file 名・file 探索・現在時刻を受け取らない（file の先頭が file 名の日付より前の記録で始まる実物があるため、file 名から日付を取らない）。

**処理ステップ**:

1. 0 バイトなら `Err(Empty)`。
2. 生バイト列の SHA-256 を小文字 hex 64 文字で `file_hash` にする（decode 後の文字列からは計算しない）。
3. CRLF で行に分割する（IO-08.2）。
4. 各行を CP932 strict（`encoding_rs::SHIFT_JIS.decode_without_bom_handling`）で decode する。どれかの行が decode できなければ `Err(DecodeFailed)`。
5. 記録ヘッダを検出する（IO-08.3）。1 つも無ければ `Err(NoRecords)`。
6. 最初のヘッダより前の行を先頭断片にする（IO-08.4）。
7. 各記録の種類を決め（IO-08.3 の IO-08-D3a）、本文の行を分類し（IO-08.5）、復元状態を決める（IO-08.6 / IO-08.7）。診断は IO-08.8 の規則で積む。
8. `EjParseResult` を返す。

**エラーハンドリング**:

致命的エラーは 3 種で、部分結果を返さない。それ以外の異常は記録単位の復元不能と診断で返す（IO-08.8）。

| 条件 | 戻り値 | 文言 |
|---|---|---|
| 0 バイト | `Err(EjParseError::Empty)` | ファイルが空です。ファイル形式を確認してください |
| どれかの行が CP932 strict で decode できない | `Err(EjParseError::DecodeFailed)` | CP932デコードに失敗しました。ファイル形式を確認してください |
| 記録ヘッダが 1 つも無い | `Err(EjParseError::NoRecords)` | 記録のヘッダがありません。ファイル形式を確認してください |

### IO-08.2 行の単位（IO-08-D2）

- 生バイトを CRLF（`0x0D 0x0A`）だけで分割する。改行の正規化（Z004 parser の NEL / LF / CR → LF）はしない。固定幅の形式で孤立した LF / CR は破損の兆候であり、正規化すると幅の検査が効かなくなるためである。
- 最後の CRLF の後が空なら行として数えない。空でなければ最後の行として扱い、診断 `MissingFinalNewline` を出し、その行を含む記録を復元不能にする。
- 24 バイトでない行、または 24 バイトの中に孤立した CR / LF を含む行は、診断 `InvalidWidth` を出し、その行を `Unknown` として残し、その行を含む記録を復元不能にする（孤立した LF / CR は行の長さの違いか、24 バイト内の CR / LF として現れる。後者は空白の除去で消えるため、分類より前に検査する）。先頭断片の行にも同じ検査をする。診断の固定文言（IO-08.8）は 24 バイト内の CR / LF の場合も「行の長さが24バイトではありません」のまま変えない。
- 行番号は 1 始まり。

### IO-08.3 記録ヘッダ（IO-08-D3）

連続する 2 行が次の両方を満たすとき、記録の始まりとする。どちらも IO-08.2 の幅の検査に通ること（24 バイトちょうどで、孤立した CR / LF を含まない）。

| 行 | バイト位置 | 形 |
|---|---|---|
| 1 行目 | 0〜4（5 バイト） | モード欄 |
| 1 行目 | 5〜20（16 バイト） | `YYYY-MM-DD HH:MM`（ASCII 数字、`-` / 空白 / `:` の位置が固定） |
| 1 行目 | 21〜23（3 バイト） | 空白 |
| 2 行目 | 0〜12（13 バイト） | 空白 |
| 2 行目 | 13〜23（11 バイト） | 数字 4 桁 + `-` + 数字 6 桁 |

- ヘッダの検出は file の先頭から順に行い、見つけたら 2 行進める。本文の途中でもこの形の 2 行があれば、そこから次の記録になる。
- モード欄を空白除去した値で `EjMode` を決める: 空 → `Normal`、`戻` → `Return`、`練習` → `Training`、`精算` → `Settlement`、`点検` → `Inspection`、`PGM` → `Program`、`PGM1` → `Program1`、`PGM3` → `Program3`、`OFF` → `Off`、それ以外 → `Unrecognized(raw)`（その記録は種類 `Unclassified` で復元不能、診断 `UnrecognizedMode`）。
- モード欄は記録の種類を決めない（下の IO-08-D3a）。使うのは、未知のモードを復元不能にすること、練習の記録と設定の記録を決めること（どちらも本文に題が無いときだけ）、取引・取引中止・入金 / 出金 / 替・領収書を受けるのを空と `戻` に限ること、戻の印を受けるのを空に限ることの 4 つ。返品の効果の解釈は BIZ が行う。
- 日時は分精度の文字列のまま返し、変換・妥当性の判断・時計の信用をしない。
- 4 桁の欄と 6 桁の番号は先頭 0 を保つ文字列で返し、連続・欠番・リセットを判断しない（[23-io-z004-parser.md](23-io-z004-parser.md) の精算メタと同じ方針）。

記録の境界をダッシュ 24 本の行にする案は、実物でその行が明細と合計の区切りだったため採らない。

#### 記録の種類（IO-08-D3a）

記録の種類（`EjRecord.kind`）は、番号印字の行（空白除去後が `＃` + 半角空白 1 個以上 + ASCII 数字 1 個以上）を除いた本文で、次の表を上から順に当て、最初に当たった行で決める。番号印字の行は種類の判定と照合に使わず、`NumberPrint` として本文に残す（取引・取引中止の明細域を除く。明細域では明細域の規則で分類する）。

| 順 | 条件 | 種類 |
|---|---|---|
| 1 | モード欄が未知（`Unrecognized`） | `Unclassified`（本文を分類しない。診断 `UnrecognizedMode`） |
| 2 | 先頭の行が精算票の題（IO-08.5 の `ReportTitle` の Z の形） | `Settlement { report, completed }`。`completed` は題と同じ帳票名だけの行（終わりの印字）が本文にあるか |
| 3 | 先頭の行が点検票の題（`ReportTitle` の X の形） | `Inspection` |
| 4 | モード欄が `練習`、または本文が 1 行以上あり、すべてトレーニングの表示の行（`ﾄﾚｰﾆﾝｸﾞﾓｰﾄﾞを` で始まる行と `･･････トレーニング･･････` の行） | `Training` |
| 5 | モード欄が `PGM` / `PGM1` / `PGM3` / `OFF` | `Settings` |
| 6 | モード欄が `精算` / `点検`（題が無い） | `Unclassified`（診断 `IncompleteRecord`） |
| 7 | 本文がちょうど 1 行で、その行が `入金` / `出金` / `替` の `Labeled` | `CashMovement` |
| 8 | 本文が `一連No.` / `領収No.` / `領収書` の `Labeled` の 3 行（この順） | `Receipt` |
| 9 | 区切りが無く、最後の行が取引中止の印 | `Cancelled` |
| 10 | それ以外 | `Sale`（区切りが無ければ IO-08.6 のとおり `IncompleteRecord`） |

- 7〜10 はモード欄が空か `戻` の記録だけに当たる（1〜6 でほかのモードはすべて決まる）。
- 精算票・点検票は題で決め、モード欄によらない。実物には、モード欄が空・`点検`・`PGM` の完了した精算票と、モード欄が空・`精算` の点検票がある。
- 練習の記録は売上に入らない（実物の精算票の件数の行と練習の記録の数で確かめた。構造所見）。設定の記録は本文に決まった形が無い（設定の印字・時計の設定の印字を含む）ため、題もトレーニングの表示も無い記録に限ってモード欄で決める。

### IO-08.4 先頭断片と EOF（IO-08-D4）

- 最初のヘッダより前の行は記録に入れず、`leading_lines` に行番号つきで返す（行種は `Unknown`）。1 行以上あれば診断 `LeadingFragment`（範囲 File）を 1 件出す。先頭断片の行ごとの `UnknownLine` は出さない。
- 記録の本文は次のヘッダの直前まで、最後の記録は EOF まで。
- EOF を記録の閉じの根拠にしない。閉じは IO-08.6 / IO-08.7 の必須行で判断する。途中で切れた記録は必須行の欠けで復元不能になり、再取得した file を再度 parse すれば復元される。

### IO-08.5 行の分類（IO-08-D5）

行種は記録の種類（IO-08-D3a）と記録内の位置で決める。行の形だけで分類すると、区切りの後の「現金」行が明細と同じ形になるためである。どれにも当たらない行は `Unknown` として残し、診断 `UnknownLine` を出し、その記録を復元不能にする。IO-08.2 の幅の検査に通らない行は分類せず `Unknown`。IO-08.9 の「未観測の形式」の列挙のうち、本節の表が受理する形は本節に従う（列挙そのものの更新は IO-08.9 の持ち主の lane が行う）。

#### 行の文法表

「区切り」はダッシュ（`-`）24 個の行。取引の記録では最初の区切りより前を明細域、後を合計域とする。取引中止の記録は区切りを持たず、本文全体を明細域として読む。「金額 token」は下の共通規則。「ラベル + 空白」は、ラベルの直後が半角空白であること。

共通の行:

| 行種 | 形 | 現れる記録 | 値の扱い |
|---|---|---|---|
| `Separator` | `-` × 24 | 取引（明細域の終わりの 1 行だけ）・精算票・点検票・設定 | — |
| `NumberPrint` | 空白除去後が `＃` + 半角空白 1 個以上 + ASCII 数字 1 個以上 | 取引の合計域と、取引・取引中止以外の記録 | 値を解釈しない（番号印字の意味づけは IO-08.9 の外） |
| `Status` | `SD設定書込み` / `SDｶｰﾄﾞ保存` / `ｽﾏ-ﾄﾌｫﾝ送信` / `SD設定読込み` / `自動設定保存` で始まる | 精算票・点検票・設定 | 結果欄（観測は `正常終了` と `異常終了`）を空白除去した文字列で保持。成否を判断しない |
| `Unknown` | 下の表のどれにも当たらない行 | どれでも | 診断 `UnknownLine` |

取引・取引中止の明細域（IO-08-D5a / D5c）:

| 行種 | 形 | 値の扱い |
|---|---|---|
| `ReturnMark` | `戻` + 半角空白 1 個以上 + `･` 1 個以上 + 空白 | — |
| `CancelMark` | `取引中止` + 半角空白 1 個以上 + `･` 1 個以上 + 空白 | — |
| `DiscountRate` | `-` + ASCII 数字 1 個以上 + `%` で始まり、残りが空白 | 値を解釈しない |
| `Correction` | `訂正` + 空白 + 金額 token だけ | 金額（符号つき。負は通貨記号なし、正は通貨記号つきを観測） |
| `Subtotal` | `小計` + 空白 + 金額 token だけ | 金額 |
| `PercentDiscount` | `％－` + 空白 + 金額 token + 任意の `*` | 金額。`*` があれば `subtotal: true` |
| `MinusKey` | `－` + 空白 + 金額 token + 任意の `*` | 金額。`*` は解釈しない |
| `Quantity` | 空白で始まり、空白除去後が `1 以上の整数` + ` 点` + 空白 1 個以上 + `@` + 単価 token（通貨記号なし、`-` なし） | 数量（ASCII 数字の 1 以上の整数）と単価（非負）。直後の 1 明細だけに掛かる |
| `Item` | 空白でない文字で始まり、末尾の空白を除いた最後の半角空白より後が「通貨記号つきの金額 token + 任意の `※`」か「通貨記号なしの負の金額 token」、その前（末尾の空白を除く）が空でない名称 | 名称（中の空白を許す）と金額。`※`（軽減税率の印）は解釈しない |
| `ItemName` | 空白でない文字で始まり、上のどれにも当たらず、直後の行が明細域の `Continued` の形 | 名称（末尾の空白を除く） |
| `Continued` | 直前の行が `ItemName` で、空白で始まり、空白除去後が通貨記号つきの金額 token だけ | 金額 |

- 判定順は表の上から下。ラベルの形（`訂正` / `小計` / `％－` / `－`）は「ラベル + 空白 + 金額 token だけ」に限るので、ラベルの語で始まる名称の明細（例: 名称の後に通貨記号つきの金額）は `Item` になる。明細域では「現金」「売掛」などで始まる名称も `Item`。
- `CancelMark` は取引中止の記録の最後の行だけに当たる（IO-08-D3a の 9）。取引の記録の明細域に現れれば `Unknown`。

取引の合計域（IO-08-D5a / D5b）:

| 行種 | 形 | 値の扱い |
|---|---|---|
| `ItemCount` | 空白で始まり、空白除去後が `整数`（任意の半角 `-`）+ ` 点` | 点数（ASCII 数字の符号つき整数） |
| `Labeled` | `対象計` / `対象計※` / `内税` / `内税※` / `合  計` / `お預り` / `お  釣` / `現金` / `ｸﾚｼﾞｯﾄ電子M` / `ｸｰﾎﾟﾝﾎﾟｲﾝﾄ払` / `売掛` / `商品券` + 空白で始まる。または空白除去後がちょうど `注）※は軽減税率適用` | prefix だけで判定。金額を読むのは `合  計` と支払行（`現金` / `ｸﾚｼﾞｯﾄ電子M` / `ｸｰﾎﾟﾝﾎﾟｲﾝﾄ払` / `売掛` / `商品券`）だけ（IO-08.6） |

| `Correction` | `訂正` + 空白 + 金額 token だけ | 金額（IO-08.6 の合計域の訂正） |
| `NumberPrint` | 共通の行の表 | — |

- 通常・返品の合計域の 2 本目の区切りは `Unknown`。

入金 / 出金 / 替・領収書（IO-08-D5d）:

| 領収書 | `Labeled` | 空白除去後が `一連No.` + ASCII 数字、`領収No.` + ASCII 数字、または `領収書` + 空白 + 金額 token | 値を解釈しない（`一連No.` の値と取引の番号の対応は IO-08.9 の外） |

#### 金額 token

1 つの共通規則で読む: 任意の符号（半角 `-` か全角 `－`）、任意の通貨記号（半角 `\` = CP932 の 0x5C、または全角 `￥`）、数字と桁区切り。

- 数字は ASCII `0`〜`9` または全角 `０`〜`９`（U+FF10〜U+FF19）、桁区切りは半角 `,` または全角 `，`。
- 符号・通貨記号・数字・桁区切りの幅が 1 つの token の中でそろわなければ受理しない（半角 `-` + 半角 `\` + ASCII 数字 + 半角 `,`、または全角 `－` + 全角 `￥` + 全角数字 + 全角 `，`）。
- 桁区切りは数字の直後だけに置ける（先頭・連続・末尾の桁区切りは受理しない）。数字が 1 つも無い token は受理しない。
- 値は `i64`。収まらない桁は受理しない（その行は `Unknown`）。
- token の直後の印（`％－` / `－` の `*`、明細の `※`）は、行の文法表がその行種に許すときだけ外して読む。ほかの位置の印は token を読めなくする。
- 観測した字形: `合  計` / `お預り` / `お  釣` / `入金` / `出金` / `現金` / 支払行 / `領収書` の金額は全角 `￥` + 全角数字 + 全角 `，`。負の取引のこれらの金額は全角 `－` + 全角数字（通貨記号なし）。明細（半角 `\`）・`対象計`・`内税`・`小計`・訂正の正の金額・精算票の値は ASCII 数字。訂正・％値引き・マイナスキー・戻の印の明細の負の金額は半角 `-` + ASCII 数字（通貨記号なし）。精算票の `AmountOnly` とラベル行は通貨記号なしの負値（`-` + ASCII 数字）を取りうる。
- 小数の数量・点数は実物にある（部門キーで小数の数量を売った日）が、数量の型（`i64`）を変えるのは単位の拡張の lane（`docs/backlog.md`）の表し方に揃えるため、本書では受理しない（その行は `Unknown`）。数量 0 と `-` つきの単価も受理しない（その行は `Unknown`）。数量 0 の数量行は Σ数量にも Σ金額にも寄与せず、記録内の照合を素通りするためである。

### IO-08.6 明細の復元（IO-08-D6）

対象は種類 `Sale` の記録で、IO-08.8 の行単位の問題が無いもの。明細域の行を次の「項目」にまとめ、出現順に下の規則を当てる。

| 項目 | 行の並び |
|---|---|
| 明細 | 任意の `Quantity` + `Item`（金額 0 以上）、または任意の `Quantity` + `ItemName` + `Continued` |
| 戻の明細 | `ReturnMark` + `Item`（金額が負） |
| 訂正 | `Correction` |
| 小計 | `Subtotal` |
| ％値引き | `DiscountRate` + `PercentDiscount` |
| マイナスキー | `MinusKey` |

「直前の項目」は、その項目のすぐ前の項目。取り消された明細・値引きは「有効」でない。

| 項目 | 条件（満たさなければ `InconsistentRecord`） | 効果 |
|---|---|---|
| 明細（IO-08-D6） | 数量行があれば 数量 × 単価 = 金額。金額は 0 以上 | 有効な明細に足す。数量は数量行の値、無ければ 1 |
| 戻の明細（IO-08-D6d） | 記録のモード欄が空（`Normal`）。`Item` の金額が負。数量行を持たない | 有効な明細に足す。数量 -1、金額は負のまま |
| 訂正・負（IO-08-D6a） | 直前の項目が有効な明細（戻の明細を除く）で、訂正の金額 = −その明細の金額 | その明細を取り消す |
| 訂正・正（IO-08-D6a） | 直前の項目が有効な ％値引きで、訂正の金額 = −その値引きの金額 | その値引きを取り消す |
| 小計（IO-08-D6b） | 金額 = それまでの有効な明細と有効な値引きの金額の和。直後の項目が `*` つきの ％値引き | なし（照合だけ） |
| ％値引き・`*` なし（IO-08-D6b） | 直前の項目が有効な明細（戻の明細を除く）。金額が負 | `EjAdjustment { kind: ItemDiscount { item_line_no: その明細の line_no } }` |
| ％値引き・`*` あり（IO-08-D6b） | 直前の項目が小計。金額が負 | `EjAdjustment { kind: SubtotalDiscount }` |
| マイナスキー（IO-08-D6b） | 直前の項目が有効な明細（戻の明細を除く）。金額が負 | `EjAdjustment { kind: MinusKey }` |

- 訂正の金額 0、`DiscountRate` の直後が `PercentDiscount` でない、`PercentDiscount` の直前が `DiscountRate` でない、`ReturnMark` の直後が負の `Item` でない、戻の印を持たない負の `Item`、数量行の直後が明細でない（数量行の連続・区切りの直前の数量行・数量行の直後が明細以外の行）は `InconsistentRecord`。
- 値引きは明細へ配らない（金額の配分は在庫ではなく金額の問題で、端数の規則が実物で決まらない。BIZ が `adjustments` から決める）。値引き・マイナスキー・訂正は点数を変えない。

合計域の照合（IO-08-D6c）。次の条件がすべてそろうとき `Restored { items, item_count, adjustments }` にする。

1. 区切りがあり、本文がヘッダだけではない。
2. 明細域に明細か戻の明細の項目が 1 つ以上ある（訂正ですべて取り消して有効な明細が 0 件になってもよい。そのとき `items` は空）。
3. 合計域に `ItemCount` がちょうど 1 行あり、その値 = 有効な明細の数量の和（戻の明細は -1）。
4. 照合の金額 = 有効な明細の金額の和 + 有効な値引き・マイナスキーの金額の和。照合の金額は、`合  計` の行があればその金額（`合  計` の行はちょうど 1 行）。無ければ、合計域の支払行（`現金` / `ｸﾚｼﾞｯﾄ電子M` / `ｸｰﾎﾟﾝﾎﾟｲﾝﾄ払` / `売掛` / `商品券`）のうち合計域の訂正で取り消されていないものがちょうど 1 行のときの、その金額。ラベルの行が金額 token を持たなければ、直後の `Continued` の金額をその値として読む。
5. 合計域の訂正は、直前の行（支払行が折り返していれば `Continued`）が支払行で、訂正の金額 = −その支払行の金額のときだけ受理し、その支払行を取り消す。
6. 合計域に `Unknown` が無い（行単位の問題として先に復元不能になる）。

- `items` は有効な明細を記録内の出現順に並べる。同じ名称の行を合算しない。取り消した明細は `items` に入れない（行は本文に残る）。
- 返品モードでも金額の符号を反転しない。返品の効果の解釈は BIZ が行い、金額の符号で返品を判定しない（戻の印の明細は印字のとおり負で、数量 -1 で返す）。
- `対象計` / `対象計※` / `内税` / `内税※` / `お預り` / `お  釣` / 注記 / 番号印字の値は照合しない。`合  計` があるときの支払行も照合しない。
- 残る限界: 合計域の行の並びと回数は、`ItemCount`・`合  計`・支払行・合計域の訂正を除いて検査しない。明細の数量と金額は点数・照合の金額と一致しているため、在庫へ渡る明細は誤らない。

条件が 1 つでも欠ければ `Unresolved` で、欠け方に応じて次の診断を出す（範囲 Record、行番号は `header_line_no`）。

| 欠け方 | 診断 |
|---|---|
| 本文がヘッダだけ、区切りが無い、明細域に明細の項目が無い、`ItemCount` が無い、`合  計` も取り消されていない支払行も無い | `IncompleteRecord` |
| 上の項目の規則の不一致、`ItemCount` ≠ 数量の和、照合の金額 ≠ 金額の和、`ItemCount` か `合  計` が 2 行以上、`合  計` が無く取り消されていない支払行が 2 行以上、照合に使うラベルの金額が読めない、合計域の訂正が支払行の取消でない、合計の計算が `i64` に収まらない | `InconsistentRecord` |

記録内の照合は取引の構造の確認であり、区間の完全性の証明ではない（ADR SPEC-STK-TIME-D5「日計合計一致だけを完全性の証明にしない」）。Z004 との照合は行わない。

### IO-08.7 明細を持たない記録（IO-08-D7）

次のとき `NoItems` にする（行単位の問題が無い記録に限る。IO-08-D7a）。

| 種類 | `NoItems` の条件 | 欠けたとき |
|---|---|---|
| `Cancelled`（取引中止） | 明細域の項目が IO-08.6 の項目の規則を満たし、`CancelMark` が最後の行に 1 回だけある | 規則を満たさなければ `InconsistentRecord` |
| `CashMovement`（入金 / 出金 / 替） | 種類の条件（IO-08-D3a の 7）のとおり | — |
| `Receipt`（領収書の発行） | 種類の条件（IO-08-D3a の 8）のとおり | — |
| `Settlement`（精算票 Z） | 先頭が `ReportTitle`（Z）。`ReportEnd` が無い中断した精算票も `NoItems`（`completed: false`） | 未知の行があれば `UnknownLine` |
| `Inspection`（点検票 X） | 先頭が `ReportTitle`（X） | 未知の行があれば `UnknownLine` |
| `Settings`（設定） | 本文が `Separator` / `Status` / `NumberPrint` / `Text` だけ（本文 0 行を含む） | 通貨記号を含む行は `Unknown`（`UnknownLine`） |
| `Training`（練習） | 条件なし（本文を分類しない） | — |
| `Unclassified` | `NoItems` にしない | 未知のモードは `UnrecognizedMode`、モード欄が `精算` / `点検` で題が無ければ `IncompleteRecord` |

- 取引中止は取引全体を無効にする記録で、商品の行を含んでも在庫を減らさない。練習の記録は売上に入らない。どちらも明細を返さない。
- 精算票・点検票の値（総売・純売・純客・現金在高・信在高・貸在高・券在高・対象計・内税・消費税合計・領収書・取引中止）を解釈せず、値の検査もしない。`completed` は終わりの印字の有無だけを表し、どの精算を区間の区切りにするか・区間・系列の意味づけは IO-08.9 のとおり IO の外で行う。

### IO-08.8 復元状態の型と診断（IO-08-D8）

- `EjRestoration::Unresolved` は明細と値引きの field を持たない。後続が復元不能の記録を誤って在庫へ使う経路を型で閉じる（bool の flag は読み出しを防げないため採らない）。
- 記録は `header_line_no` と本文の行（行番号・生の文字列・行種）を復元状態によらず常に保持する。診断と訪店時の確認のためである。本文の行から明細を組み直すのは呼出し側の責任であり、そうした値は本関数の復元の保証を持たない。
- 先頭断片・ヘッダ 2 行・本文の行番号を合わせると、1〜N（N は file の行数）をちょうど 1 回ずつ覆う。どの行も記録・先頭断片のどちらかに必ず入る。
- 行単位の問題（`UnrecognizedMode` / `InvalidWidth` / `UnknownLine` / `MissingFinalNewline`）がある記録は、IO-08.6 / IO-08.7 の照合をせずに `Unresolved` とし、`InconsistentRecord` / `IncompleteRecord` を重ねて出さない。行が読めない記録の照合結果は、欠けた行が合計の行だった可能性があり、原因を示さないためである。
- 未知のモードの記録は `UnrecognizedMode` 1 件で表し、本文の行（行種 `Unknown`）ごとの `UnknownLine` は出さない。練習の記録の本文も行ごとの診断を出さない。幅違反と最終改行なしは未知のモード・練習の記録でも出す。
- 種類 `Unclassified` の記録は常に `Unresolved`。
- `Unresolved.reasons` は、その記録で出た診断の code を初出順に重複なく並べたもの。
- `diagnostics` は file 内の出現順に並ぶ: `LeadingFragment`、先頭断片の `InvalidWidth`、続いて記録ごとに `UnrecognizedMode`、本文の行の診断（行順）、`MissingFinalNewline`、記録の照合の診断。

#### 診断の code・範囲・固定文言

message は code ごとの固定文言と完全に一致し、行の生の文字列（名称・金額・日時・番号）を含めない。後続が診断を log・画面へ出しても実データが流れないようにするためである。code と文言は文法の追加（D-105）で変えない。

| code | 範囲 | `line_no` | 発生条件 | message |
|---|---|---|---|---|
| `UnknownLine` | Line | その行 | 行種が `Unknown`（先頭断片・未知のモードの本文・幅違反の行を除く） | 解釈できない行があります。この記録は明細を復元できません |
| `InvalidWidth` | Line | その行 | 24 バイトでない行、または 24 バイトの中に孤立した CR / LF を含む行（先頭断片を含む） | 行の長さが24バイトではありません。この記録は明細を復元できません |

### 採らなかった案

| 案 | 採らない理由 |
|---|---|
| 改行を正規化してから分割する（Z004 parser と同じ） | 固定幅の形式で孤立した LF / CR は破損の兆候で、正規化すると幅の検査が効かない |
| ダッシュ 24 本の行を記録の境界にする | 実物では明細と合計の区切りだった |
| 行の形だけで行種を決める | 区切りの後の「現金」行が明細と同じ形になり、架空の明細が増える |
| file 名から日付を取る | file の先頭が前日付の記録で始まる実物がある |
| 復元の可否を bool の flag で返す | flag を見ずに明細を読み出せてしまう |
| 番号を数値にする | 先頭 0 が落ち、意味が未検証の値に数値の意味を与える |
| 記録の種類を見出しのモード欄で決める（2026-09 までの IO-08.3） | モード欄が `精算` でない完了した精算票と、取引と読まれる点検票が実物にある。精算の区切りを取りこぼす（IO-08-D3a） |
| 練習の記録の本文を取引の文法で分類する | 練習は売上に入らず、明細を返さない。練習にだけ現れる印・支払行の文法を足しても在庫に使わない（IO-08-D3a） |
| 設定の記録の本文を行ごとの文法で読む | 設定の印字の中身はレジの設定項目（時計の設定を含む）で決まった形が無い。通貨記号を含む行だけを `Unknown` にして、取引の行の紛れ込みを止める（IO-08-D5d） |
| 中断した精算票を `IncompleteRecord` のままにする | 中断は実物にある既知の形（題・値・送信の異常終了で、終わりの印字なし）。復元不能にすると未知の記録と区別できない。`completed: false` で返し、区間の区切りに使うかは IO の外（IO-08-D7a） |
| 訂正の取消先を記録内の同額の明細から探す | 実物の訂正は常に直前の行の取消。離れた行への対応は推測で、別の明細を消し得る（IO-08-D6a） |
| 値引きを明細の金額へ配る | 在庫ではなく金額の問題で、端数の丸め方が実物で決まらない。`adjustments` で返し、配分は BIZ（IO-08-D6b） |
| `合  計` が無いとき支払行の金額を足して照合する | 2 種の支払の併用は `合  計` がある取引だけで観測した。足し合わせは未観測の並びを受理する（IO-08-D6c） |
| 戻の印の明細を数量 1 で返す | レジ自身が点数で −1 と数え、点数の照合はその数え方で成り立つ（IO-08-D6d） |
| 番号印字を記録の種類にする | 番号印字は取引の合計域・設定・入金の記録の中に現れ、独自の見出しを持たない。行種にとどめ、意味づけは IO の外（IO-08-D3a） |
| 小数の数量・点数を受理する | 数量の型（`i64`）の変更は単位の拡張の lane の表し方に揃える（`docs/backlog.md`）。それまで小数の行は `Unknown` |
