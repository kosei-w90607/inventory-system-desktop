## Goal

Goal Invariant:

### 最小完了条件

- Draft PR への push（`opened` / `reopened` / `synchronize`）のたびに hosted CI が changes と changed 分類の job を回し、結果が PR の check `Draft (no merge evidence)` に出る。Ready 後（`ready_for_review` / `synchronize`）と dispatch の run だけが `Merge gate` を出し、merge の証拠は今と同じく Ready 後の run の `Merge gate`。
- `bash scripts/local-ci.sh full` は merge 前の必須の手順でなくなり、正本（`docs/ci.md`・merge-evidence・`docs/DEV_WORKFLOW.md`）と入口（`AGENTS.md`・Skill・command・DEV_SETUP_CHECKLIST）が同じ 1 つの説明を持つ。
- 同乗 4 件: pre-push の Rust gate から `cargo test` を外す（fmt / clippy / traceability / PK5 は残す）。reviewer の doc check の再実行を外し hosted の docs job を読む。`design_compliance_test` の別実行の記述を消す。npm security monitor を日次に戻す。

### 失敗定義

- Draft の run が `Merge gate` の名前の check を出す、または required 名の skipped / neutral を Draft で出す（MG-D3 と merge-evidence `:43` の禁止を破る）。
- helper（`scripts/pr-gate.py`）が Draft の run を merge の根拠に数える、または Ready 後の run 以外の古い green で merge できる。
- Draft の hosted が red のときに、push・review・record・Draft のままの修正といった正当な作業が止まる（Draft の red は feedback で、止めるのは Ready 後の red だけ）。
- pre-push から外した `cargo test` を Draft の hosted（rust_test）が担わない。
- 正本の一方だけを直し、`local-ci.sh full` を merge 前の必須と書く文や `design_compliance_test` の別実行を求める文が live の文書に残る。

### 非目的

- strict（MG-D1）・helper の merge 条件（Ready 後の run の `Merge gate`）・`workflow_dispatch` の意味（CI-TRIGGER-D1 の recovery dispatch）の変更。
- hosted の job の構成・cache policy・CI token・npm audit の warn-only の変更。
- `local-ci.sh` の削除、`.local/ci-evidence/` の廃止（任意の道具として残す）。
- 形骸化の棚卸しの残り（Plans.md の刈込み、Workspace Access の wrapper、MANUAL §5.4、agent-guidance の profiles / evals）。

Priority: `Goal Invariant > Acceptance Criteria > supporting evidence`。AC や証跡作業が Goal Invariant を前進させない場合は、Goal を置き換えず簡略化・defer・削除する。

## Boundary / Wire Contract

check-run の名前と aggregate の入力が wire。

- producer: `.github/workflows/ci.yml`（aggregate の `name` 式 → GitHub の check-run 名。`toJSON(needs)` → `NEEDS_JSON`）。
- consumer: GitHub ruleset（`.github/merge-gate-ruleset.json:26` context `Merge gate`、integration_id 15368）、`scripts/pr-gate.py:396-398`（check suite の `Merge gate`）、`scripts/ci/check-required-jobs.sh`（`NEEDS_JSON`）。
- wire type: check-run 名の文字列（`Merge gate` / `Draft (no merge evidence)`）、`NEEDS_JSON` の JSON（job → result、changes → outputs の 9 key）。
- internal type: name 式の真偽（`workflow_dispatch || draft == false`）、Python の dict。
- precision/range: 名前は完全一致。`NEEDS_JSON` の result は `success` / `skipped` だけを受理。
- round-trip path: Draft の run → `Draft (no merge evidence)`（required に数えない）。Ready / dispatch の run → `Merge gate` → ruleset と helper が読む。
- invalid input: Draft の run が `Merge gate` を出す（`ci-workflow.test.sh` の name の期待と Draft の名前の mutation が拒む）。Draft で required 名の skipped（aggregate が走るので skipped にならず、名前も違う）。
- compatibility: check-run 名・ruleset・helper・`NEEDS_JSON` の形は不変。Draft の run が `skipped` から実行に変わるだけ。
