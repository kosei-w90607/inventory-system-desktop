## Risk

Risk: R3

Reason:
POS CSV（Z004）の読み取りの契約を変える（DEV_WORKFLOW Risk Tiers の「POS CSV」）。行の分類が変わり、今まで黙って捨てていた行が行エラーになり、今まで毎回エラーだった行が読み飛ばしになる。プレビューのエラー詳細（最大 100 件）の選び方が変わる（`invalid_jan` の行を先に選ぶ）。DB の schema・Tauri command・DTO・bindings・画面の code・route は変えない。破壊的な操作・実データの露出・取り消せない操作は無く、Z004 の commit は停止中なので R4 ではない。

## Goal

Goal Invariant:

### 最小完了条件

- 実データの Z004 にある形（金額が 1,000 以上で 3 桁区切りのカンマ付き）の行が、正常な行として BIZ-03 のマスタ照合へ届く（`invalid_number` にならない）。
- コードが全桁 0 で個数か金額が 0 でない行（PLU の登録を消した枠、コードを持たない通常 PLU の売上）が、黙って読み飛ばされず、`invalid_jan` の行エラーとして「商品コードの無い枠（メモリNo.）に売上がある」文言で知らされる。取込みは completed_partial になり、エラーはプレビューのエラー詳細と取込み記録の詳細に出る（owner 決定 TD-105）。プレビューのエラー詳細は最大 100 件で、`invalid_jan` の行を先に選ぶため、未登録 JAN の行が 100 件を超えても落ちない（32 §15.3 手順 5c）。
- 個数・金額とも 0 の本当の空スロットは今どおり読み飛ばされる。コードが 13 桁 JAN にならない枠（8 桁独自コード + `EEEEEE`）も、個数・金額とも 0 なら読み飛ばされ、毎回のエラーにならない。
- 設計正本（23・32・pos-tables・io-task-specs）と実装・test が同じ契約を持つ。

### 失敗定義

- 個数か金額が 0 でない行が、正常な行にも行エラーにもならずに消える経路が残る。
- 区切りの崩れたカンマ（`1,23` 等）や小数を、黙って別の整数として読む。
- 13 桁 JAN の 0/0 の行を IO で捨て、ADR D4 の相殺の判定の入力を失う。
- error 種別・`csv_import_errors` の CHECK・`CsvImportErrorType`・`src/lib/bindings.ts`・画面の code・`parse_plu_register_snapshot` の契約が変わる。
- 既存の test を弱める・消す。

### 非目的

- clear 行の売上を元の商品へ戻すこと（TD-105 で不採用）。
- Z004 の小数の数量（単位の拡張）、日報（Z001/Z002/Z005）の読み取り（lane B）、EJ（lane D）。
- 停止中の Z004 の commit を動かすこと（㉘ ⑤）。時点証拠 ADR の書き換え。
- PLU 書出しに clear の時期の案内を足すこと。

Priority: `Goal Invariant > Acceptance Criteria > supporting evidence`。AC や証跡作業が Goal Invariant を前進させない場合は、Goal を置き換えず簡略化・defer・削除する。

## Boundary / Wire Contract

- producer: レジ（CASIO SR-S4000 / CV17）が SD に書く Z004 の CSV（layout A と従来 shape）
- consumer: IO-02 `parse_z004` → BIZ-03 `parse_and_validate`
- wire type: CP932・ダブルクォート囲みの 5 フィールドの文字列。個数・金額は `-?[0-9]+` または `-?[1-9][0-9]{0,2}(,[0-9]{3})+`（カンマなしの値も式で判定し、`+5` を拒む。先頭グループは 0 で始まらず、`0,123` を拒む）
- internal type: `ParsedRow.quantity` / `amount` は i32（不変）。行エラーは `ParseError { error_type: InvalidJan | InvalidNumber | InvalidFormat }`（不変）
- precision/range: i32 の範囲。小数は受けない
- round-trip path: なし（読むだけ）。`csv_import_errors.raw_quantity` / `raw_amount` は、IO の ParseError 由来の行（`invalid_format` / `invalid_jan` / `invalid_number`）では取得できた field の元の文字列（カンマ付きのまま。field が 5 未満の `invalid_format` で取得できなかった field は `""`）。`unmatched_product` など BIZ が整数から作る行は整数の文字列表現（金額 `1,234` の未登録 JAN の行は `"1234"`、32 §15.3 4b）。BIZ-03 の 4b / 4c の raw 値の作り方は変えない（S5 は手順 5c の items の選び方だけ）
- invalid input: 区切りの崩れ・小数・空 → `InvalidNumber`。コード全桁 0 で売上あり → `InvalidJan`（D-103 の文言）
- compatibility: Tauri command・DTO・`CsvImportErrorType`・bindings・DB は不変（AC7）。従来 shape と layout A の両方に同じ規則を当てる
