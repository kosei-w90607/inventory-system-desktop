## Goal

Goal Invariant: 店主が、取り込んだ Z001 の全行を、日次売上の「レジ日報（公式）」で、レジの帳票と同じ名前・同じ並びで見られる。同じ日に 2 回以上取り込んだ日は取込みごとに分けて見られる。

### 最小完了条件

- 日報を取り込んだ日の日次売上を開くと、総売上 / 純売上の下に h3 `日計（Z001）` と、Z001 の全行（総売・純売以外の行、0 の行を含む）の表が、保存されたラベルのまま `sort_order` の順に出る。個数/件数は総売の行が個数（小数はレジと同じ形、例 `12.5`）、それ以外が件数で、値の無い欄は `—`。
- 同じ日に 2 回以上取り込んだ日は、取込みの古い順に取込みごとの表が並び、各表の上に `{N}回目の取込み（取込み日時 YYYY-MM-DD HH:mm）` が出る。総売上 / 純売上・支払集計・部門別集計は今までどおり合算で、section の文が UI-09a-D16 の 2 回以上の日の文になる。取り消した取込みの行は出ない。
- 既存 2 表の見出しが `支払集計（Z002）`・`部門別集計（Z005）` になり、行・合算・列は変わらない。
- owner が Windows native（DPI 125% / 150%）で before / after を並べ、L3-1〜L3-3 を PASS にする。

### 失敗定義

- Z001 の総売・純売以外の行が画面に出ない、または同日 2 回の取込みの Z001 が合算・最新 1 回だけ・逆の順で出る。
- 個数が 100 倍の値で出る、NULL が 0 や「未取得」で出る、0 の行が隠れる、ラベルが言い換えられる。
- 既存の表示（総売上 / 純売上の metric、支払集計・部門別集計の合算と行、未取込みの note、部門未対応の warning、`1回の取込みを合算` の文、商品別明細との分離、日次 CSV の列）が変わる。
- 取込み・取消・parser・DB schema・月次の画面・ホームに diff が出る（下の Non-scope）。
- 実店舗の CSV 本文・値・ラベルが tracked file に入る。

### 非目的

- 印刷、紙（Excel + 印刷 + バインダー）の代わりになるかの受入判定（UI-09a-D13）、月次への展開、取込み履歴の一覧と後日の取消の導線。
- Z002 / Z005 の行・合算の変更（見出しに出どころを添える以外）。既存の支払集計（Z002）の合算の潜在バグ（backlog の独立した項目。Coordinator が 2026-10-06 に持ち帰りデータの Z002 を数え、現金・クレジットを含む行が 2 行以上ある file は 0 件。別の項目として保留）。
- 精算回数・精算時刻の保存と表示（`N回目の取込み` は取込みの順で、精算の順ではない、UI-09a-D16）。
- UI-09a-D16 の文字列や見せ方の変更（L3 で読み違えが出たら Gated Amendment で直す）。

Priority: `Goal Invariant > Acceptance Criteria > supporting evidence`。AC や証跡作業が Goal Invariant を前進させない場合は、Goal を置き換えず簡略化・defer・削除する。

## Boundary / Wire Contract
