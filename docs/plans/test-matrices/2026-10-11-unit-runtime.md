## Failure Modes

- 浮動小数を通して `0.29` m が 28 cm になる、表示した `1.3 m` を保存し直して 127 cm が 130 cm になる。
- 長さの商品の金額を基準数量で割らず 100 倍になる（入庫・廃棄・手動販売）。
- 行ごとの丸めと合計の丸めが場所ごとに違い、同じ明細から違う金額が出る。
- 新しい個数の単位（`ball` 等）が在庫少の SQL のどちらの分岐にも入らず、在庫少に出ない。
- formatter の `default` が新しい単位を `—` で出す。
- v8 で `products` の行・列・index・FK が欠ける、TX の中で失敗したのに表・版が変わるか `foreign_keys` が戻らない、COMMIT の後の `foreign_keys` の復元の失敗を「何も変わっていない」と扱う。
- 商品 CSV の `玉` が取込み全体を止める。CSV の上書きで単位が変わる。`m` の行の `初期在庫` `25` が 25 cm で入る。
- 長さの商品の数量を cm の整数のまま出す画面が残る（日次売上の `130`・`¥7`、販売点数の `130 点`）。
- 入力の行の再追加・統合が `1.3` を整数でないと見て `1` に戻す。手動販売で `cm` の商品が数量 1（1 cm）で入り、金額が 1/100 になる。
- 商品 CSV の負の初期在庫が取り込まれ、在庫が負・変動が 0 行で整合性が崩れる。
- 月次の部門別の表に数量が出ない。`integrity_check` の操作ログに単位が残らない。一括価格改定の画面が上限の外の値で command を送る。
- 行の金額を JS の number で受けて 1/100 円ずれる。
- 上限の外の数量・在庫・売価・原価が保存される。在庫を動かさない明細（レジ処理済みの返品、在庫に連動しない商品の売上）が上限の検査を通らない。移行の前に保存済みの上限の外の値がそのまま残る。
- 既存の `pcs`・`cm` の商品の値・表示の意味・評価額が変わる。

## Negative Paths

- missing input: m の欄が空 → 入力の error。商品 CSV の `在庫単位` が空 → `pcs`。
- invalid input: m の小数 3 桁・指数・符号、0 を受けない数量欄の `0`、数量・在庫・売価・原価の上限超え（一括価格改定の画面の案を含む）、負の初期在庫（商品 CSV の `pcs,-1`、wire の `Some(-1)`）、商品 CSV の `kg`・`m` の行の `25.155`。
- duplicate/ambiguous input: 同じ商品の再追加（cm の整数で足す）。商品 CSV の上書きで単位が違う行。
- unknown reference: DB に一覧に無い単位の行 → repo の読取りの error。`MovementTable` の対応に無い商品コード → 整数で出す。
- dependency missing: 準備照会の command（`get_pos_stock_readiness`）は無いので、在庫連動の提案は単位の種類だけで決める。時点証拠の migration は未配線なので v8 は v7 の列だけを写す（後に入る lane が `products` の列と `stocktake_recounts` を扱う）。
- permission/write failure: v8 の TX の中の失敗 → 表・版が戻り `foreign_keys` が元の値。COMMIT の後の `foreign_keys` の復元の失敗 → 版 8 が残り、接続を破棄して再起動で開く（MNT-03-D1）。create の TX の中の上限の検査 → TX 全体が戻る。
- dry-run side effect: 商品 CSV と商品別売上 CSV の preview は DB を変えない（今どおり）。
