# Test Design Matrix: CI の二重を削る

Plan Packet: [2026-09-30-ci-dedup.md](../2026-09-30-ci-dedup.md)。`D1`〜`D7` は packet の「設計判断」の D1〜D7。行番号は main `2194ed56` のもの。

## Risk

Risk: R3

## Contracts Under Test

- D1: `ci.yml` の changes job は `if` を持たず、aggregate の `if` は `always()` だけ。aggregate の name 式は Draft で `Draft (no merge evidence)`、Ready / dispatch で `Merge gate`（不変）。Draft でも `check-required-jobs.sh` が同じ検査を行う。
- MG-D2 / MG-D3: aggregate は分類失敗でも走って非 0。Draft は required 名（`Merge gate`）の check を出さず、required 名の skipped も出さない。
- D2: pre-push の Rust gate は `cargo fmt --check` → `cargo clippy --all-targets --all-features -- -D warnings` で、`cargo test` を呼ばない。traceability・PK5・docs・env・frontend の gate は不変。
- D3: `local-ci.sh` の evidence に `MERGE_EVIDENCE_VALID` の行が無い。他の行（HEAD / tree / RESULT / EXIT_CODE / EVIDENCE_FILE）と symlink の検査は不変。
- D6: npm security monitor の `on.schedule` は cron 1 つで日次（日・月・曜日が `* * *`）。
- D4 / D5 / S6: live の文書に Draft で runner を止める文、`local-ci.sh full` を必須とする文、`design_compliance_test` の別実行を求める文が残らない（AC6 の `rg`。自動 test は `ci-workflow.test.sh:199-206` の逐語の行だけ）。
- D7: helper の `ci()`、`check-required-jobs.sh`、classifier、pre-push の Ready 拒否・merged 拒否・WARN、local-ci の symlink 検査、cache・token・Node pin・npm audit は変えない。

## Failure Modes

- Draft で changes が skip に戻り、下流の job と aggregate が走らない（D1）。
- Draft の aggregate が `Merge gate` の名前で出る、または required 名の skipped が Draft で出る（MG-D3）。
- aggregate に `needs.changes.result == 'success'` の前提が付き、分類失敗で aggregate が skip される（MG-D2）。
- Draft の aggregate の赤が merge や push を止める（D1 の過剰。required 名でないこと・pre-push と helper の record が CI を読まないことで防ぐ）。
- pre-push に `cargo test` が残る、または clippy / fmt / traceability まで消える（D2）。
- `MERGE_EVIDENCE_VALID` が evidence に残る、または `RESULT` / `EXIT_CODE` など他の行まで消える（D3）。
- cron が週次のまま、または cron が 2 つになる・schedule が消える（D6）。
- `docs/ci.md` の逐語で固定された行（CI-TRIGGER-D1 の表など）を S6 が壊す（`ci-workflow.test.sh` が red）。
- helper が Draft の run を merge の根拠に数える（D7。helper を変えないので既存 test が守る）。

## Negative Paths

- missing input: `NEEDS_JSON` の job・key の欠落 → `check-required-jobs.sh` が非 0（`merge-gate.test.sh:23-28`、不変）。schedule が無い → `validate_monitor_schedule` が red。
- invalid input: changes の分類が不正な値 → aggregate が非 0（不変）。cron の曜日が `0` → red（MU7）。
- duplicate/ambiguous input: 同じ head に Draft の run と Ready の run → helper は `created_at`・id の最大を取る（P2、不変）。schedule の cron が 2 つ → red。
- unknown reference: `gh` が無い・PR の照会失敗 → pre-push は push を止める（不変）。
- dependency missing: hosted の ruby / ripgrep / python の欠落 → workflow job が赤（Draft でも見える。本 lane の動機）。
- permission/write failure: CI token は `contents: read` のまま（`ci-workflow.test.sh:86`）。
- dry-run side effect: helper `status` は read-only のまま（Draft の run が latest でも comment を書かない）。

## Boundary Checks

- threshold: なし（本数・時間の閾値を AC にしない。所要時間は Contract Probe の実測の参考値）。
- null/default: changes の `if` が無い = 常に走る。`github.event.pull_request.draft` が null（dispatch）→ name 式は `Merge gate`（不変）。
- empty/non-empty: 分類が全部 false（例: `.local` だけの変更は起こらない）でも changes・docs・aggregate は走る（不変の `docs: True` の要求）。
- min/max: cron の分・時は今の値（`0 21`）。
- status/policy enum: aggregate の name は 2 値、`check-required-jobs.sh` の result は `success` / `skipped` だけ受理（不変）。
- wire type: check-run 名の文字列、`NEEDS_JSON`、cron の文字列。
- internal type: name 式の真偽、Python の dict、ruby の YAML。
- producer/consumer: `ci.yml` → GitHub の check-run → ruleset / helper。`ci.yml` → `NEEDS_JSON` → `check-required-jobs.sh`。
- round-trip token: 該当なし。
- precision/range: 該当なし。
- cross-language parse: YAML（ruby）と GitHub expression（GitHub 側）。`ci-workflow.test.sh` は式を文字列として逐語で比べる。

## Compatibility Checks

- old schema/input: `check-required-jobs.sh` の `NEEDS_JSON`、helper の run の選び方、classifier の 9 key、ruleset は不変。旧い Draft の run（`skipped`）が残る PR は base 同期で新しい `ci.yml` を取り込むまで旧い振舞い。
- new schema/input: なし（Draft の run が `skipped` から実行に変わるだけ）。
- output order: `ci.yml` の job の順・`NEEDS_JSON` の key の順は不変。
- optional field behavior: changes の `if` の不在。

## Mutation-style Adequacy Questions

mutation は対象経路の観測結果を変えるものを選び、写しに実注入して red を確かめる（packet AC7）。

- If a mock value is changed so it differs from the design-doc expected value, which assertion proves the implementation used the correct source and not the mock's accidental constant? — `ci-workflow.test.sh` の期待は `ci.yml` の文字列と独立に test に書く（name 式・`if` の逐語）。fake の `gh` / `cargo` は呼出しの記録だけで値を返さない。
- If invalidate/refetch changes the value before versus after the operation, which test proves the lifecycle order and preserved snapshot are correct? — helper の run の選び方は不変で `pr-gate.test.py` が持つ。Draft → Ready の順は AC2 の実物と P2。
- If a key branch is inverted, which test fails? — name 式の反転（Draft で `Merge gate`）は MU3。changes の `if` の復活は MU1。aggregate の `if` の復活は MU2。
- If a threshold comparison changes, which test fails? — 閾値は無い。
- If a guard is removed, which test fails? — aggregate に changes の success 前提が付く（guard の追加）は MU4。pre-push から clippy が消えるのは MU6。
- If an output field is omitted, which test fails? — evidence の `RESULT` / `EXIT_CODE` を消せば `local-ci.test.sh:70`・`:100`。`MERGE_EVIDENCE_VALID` を戻せば MU8。
- If output order changes, which test fails? — pre-push の fmt → clippy の順は `pre-push.test.sh:295-303`（fmt の失敗で clippy が呼ばれない）。
- If dry-run performs a side effect, which test fails? — 該当なし（helper は不変）。
- If a JSON number crosses JavaScript safe integer range, which test fails? — 該当なし。
- If a state token is round-tripped through browser/client code, which test fails? — 該当なし。

## Residual Test Gaps

- GitHub の実行（Draft の run で job が走る、check-run の名前、`ready_for_review` の run が latest になる）は静的 test で作れない。本 lane の PR の AC2 と Contract Probe P1〜P3 の実測で確かめ、後続の lane では Ordinary Operation の列が実物の確認になる。
- 「Draft の赤が正当な作業を止めない」は required 名でないこと（ruleset の JSON）と pre-push・helper の record が CI を読まないこと（code の不在）による。ruleset の実効の照合は helper `rules()`（不変）が持ち、本 lane は test を足さない。
- npm security monitor の日次の起動の実物は merge 後の `gh run list --workflow npm-security-monitor.yml` で見る（AC にしない）。
- live の文書の文（S6）は AC6 の `rg` で確かめ、`ci-workflow.test.sh` の逐語の検査には足さない（文書の文を test で固定する範囲は CI-TRIGGER-D1 の表など既存の分だけ）。
- `.local/` の checklist・雛形の「L1 full」の記述は tracked 外で、本 lane の merge 後に Coordinator が直す（Non-scope）。
