## Contracts Under Test

- SPEC-STK-TIME-D10: 全数読取りの行を、置き場の識別子と一緒に列挙の前に置き、条件を満たした読取りだけが完了にする。行を置くのは自動で見つけた取外し可能な drive の root の読取りだけで、利用者が場所を選んだ root の読取りは置かない。全数読取りは、行を置く前から完了・失敗まで、同じ DB に対する唯一の操作である（読取りの排他）。読取りの中で初めて受領した資料に、その読取りの行の ID（`first_scan_id`）を INSERT のときだけ書く（読取りの外の受領は NULL）。実測の保存 TX が `source_scan_cursor` を採る。全部実測後の条件 1〜3（資料と直前の精算の資料の両方が、実測の保存より後に完了した全数読取りより後に、同じ置き場の完了した全数読取りの中で初めて受領された）を全て満たす資料だけを After にし、ほかは今までどおり判定不能にする。基準は最新の有効な実測で、数え直しの保存の後は同じ 2 つの精算の資料が改めて判定不能になる（限界）。全部実測後の枝は、外部前提の gate の証拠がそろうまで code に入れず、保存は枝の有無に依らず続ける。枝を入れる変更は、全ての実測の cursor をその時点の読取りの最大 ID へ引き上げ、全ての資料の `first_scan_id` を NULL にする migration を同じ変更に入れ、有効にする前に保存した行と値を判定に使わない。保存の不具合が分かったときは、同じ migration をもう一度当てる。
- SPEC-STK-TIME-D4: 判定の表の既存の行（非連動・未実測・旧記録・実測開始前に受領済み・判定不能）と出口・flag の理由・解消の規則が変わらない。「実測開始前に受領済み」を D10 より先に見る。共有 JAN の行は、D10 の実測後でも保留のまま。
- SPEC-STK-TIME-D5a: 骨で決まる分。区間の終端の候補（同じ machine_no の、完了した日計明細かＰＬＵの精算票を日時で抽出する。番号の差〈題の末尾 + 1〉で対応づけない）、候補が 1 件であることだけでは対応づけを確定しないこと、区切りにしない記録、欠け、読めない記録、評価の順（欠けと読めない記録 → 対応づけの確定 → 前回の証明）、番号の比べ方、「前回」の候補。対応づけを確定する条件（未決）の test は日次の EJ 取込みの lane の Matrix が持つ（Residual Test Gaps）。
- SPEC-STK-TIME-D8 / D8-K1: `pos_source_scans` の未完了と完了の形、`pos_import_sources.first_scan_id` の形、`source_scan_cursor` の kind ごとの NULL / NOT NULL。
- ADR「㉘ への引継ぎ」の合格条件（TD-223）: 数える → アプリ終了 → OS 再起動 → 後日の取込みの通し。

## Failure Modes

- 数える前の販売を含む資料を全部実測後と判定し、要再確認なしで二重に引く（黙って在庫が現物より少なくなる）。
- 数えた後の販売の資料を全部実測前と判定し、引かない（D10 は Before を足さないので、既存の規則が変わらないことで守る）。
- 正常な入力なのに、いつまでも判定不能のまま残る（数え直さずに置いた商品に、数えてから 3 つ目以降の精算でも要再確認が付く。前回と今回の締めの資料を完了した読取りで受領している場合）。
- 数え直しの保存の後に、古い実測を基準にして全部実測後と判定する（数え直しより前の販売を含む資料を二重に引く）。限界（数え直しの後の 2 つの精算の資料は判定不能）を「自動に戻る」と取り違える。
- 途中で失敗した置き場の読取りが、後の実測の「保存より後の読取り」に数えられる。
- 2 つの全数読取りが重なり、先に行を置いた読取りが、後から始めた読取りの受領した資料を受領済みと対応づけて完了する（その読取りの時点で置き場にあった資料が、後の初回受領に見える）。
- 利用者が場所を選んだ root（SD の写しの folder）の読取りが行を置き、別々の写しが同じ識別子の「同じ置き場」になる。
- EJ の欠け・読めない記録・対応づけが確定しない区間（日時の合う精算票が 1 件あるだけの区間を含む）を「完全」と扱い、売れて戻った商品を見逃す。
- EJ の記録が足りないだけの区間を、数え直しでしか解けない登録の変化に落とす。
- 番号の reset・媒体の入替・別の媒体の読取り・ファイルを選ぶ経路の資料・読取りの途中の別の経路の受領・途中で失敗した読取りの中の受領・後から受領した古い資料・後から付いた同一性拒否で、別の精算を直前の精算と取り違える、または置き場に無かったと数える。
- 判定を無効にした build が全部実測後を返す、または保存を止めて後から有効にできなくなる。無効の間に保存した行と値、保存の不具合のあった間の行と値（指す行が無い ID を持つ `first_scan_id` を含む）を、有効にした後・直した後も根拠に使う。

## Negative Paths

- missing input: 直前の精算の資料が無い → Unknown。`first_scan_id` が NULL の資料（P でも F でも）→ Unknown。実測の保存より後の完了した行と、その後の同じ置き場の完了した行がそろわない → 何も After にならない。置き場の識別子を取れない・利用者が場所を選んだ root → 行を置かない（受領は残り、`first_scan_id` は NULL）。区間の EJ が無い → EJ 待ち。
- invalid input: 読めない資料が窓にある読取り → 未完了。未完了の行を指す `first_scan_id`、指す行が無い `first_scan_id` → 条件不成立。比べられない settlement_no、形の違う日付 → 条件不成立。
- duplicate/ambiguous input: 直前の番号の資料が 2 つ（同一性の衝突）→ Unknown。日時の合う完了した精算票が 1 件あるだけ → それだけでは確定しない（EJ 待ち）。2 件以上あるときの扱いは未決。同じ番号で中身の違う EJ の記録 → 欠け扱い。
- unknown reference: 別の machine_no・別の帳票種別の資料 → 直前の資料に数えない。識別子の違う読取り → 組にしない。
- dependency missing: Z004 を SD から読む経路が無い（ファイルを選ぶ経路だけ）→ 今の ADR と同じ結果。日次の EJ 取込みの lane の設計が対応づけを確定する条件を決める前 → どの区間も EJ 待ち。
- permission/write failure: 行を置けない読取りは観測にしない。排他を取れない間（別の操作の途中）は読取りを始めない。有効にする migration は 1 つの TX で、失敗したら cursor も `first_scan_id` も変えない。cursor を採れない保存は保存 TX 全体が失敗。
- dry-run side effect: preview は在庫・flag を変えない（資料の受領と拒否の証拠だけ。ADR D2・D4）。SD の読取りは SD に書かない（IO-09-D3）。

## Boundary Checks

- threshold: `C.source_scan_cursor < O.id`（等しい = 保存の時点で既にあった行は O に使えない）、`O.id < O′.id`（P の初回受領の読取りが O 自身では成り立たない）、`O′.id <= O″.id`（F の初回受領の読取りは P のものと同じか後。前では成り立たない）、`P.first_scan_id = O′.id`・`F.first_scan_id = O″.id`（等しいことだけを見る。範囲で推さない）、`P.settlement_date` と `F.settlement_date` が `O.window_from` の翌日以降（当日は成り立たない）。`O.window_from` は O の読取りの日の前日以前（当日は書かない）。D5a の候補に入れる日時の幅は未決（観測は精算日時 − 記録の日時が 0 分か 1 分）。
- null/default: 未完了の行の NULL（`window_from`・`completed_at`）、読取りの外の受領の `first_scan_id` の NULL、kind ごとの cursor の NULL。恒久の DEFAULT を付けない。
- empty/non-empty: 窓に資料が 1 つも無い置き場の読取りは完了できる、読取りの行が 0（cursor 0。有効にする migration でも 0）、実測が 0 行・資料が 0 行の DB への migration は何も変えない、空の識別子は拒否、`first_scan_id` の 0 は拒否。
- min/max: settlement_no が 0 のとき直前（−1）は無い。桁あふれの番号は比べられない値。
- status/policy enum: 分類の出力は Before / After / Unknown のまま（増やさない）。flag の理由は 5 つのまま。
- wire type: 無し（wire に出さない）。
- internal type: ID・`first_scan_id`・cursor は i64、日付は YYYY-MM-DD の文字列、識別子は等しいかどうかだけを比べる文字列。
- producer/consumer: packet の Boundary / Wire Contract。
- round-trip token: 無し。
- precision/range: packet の「値ごとの保証の表」。
- cross-language parse: 無し（Rust と SQLite の中だけ）。

## Compatibility Checks

- old schema/input: 時点証拠 schema は registry に未登録（D-109）。登録の前に列と表を足すので、既存の DB の移行は無い。㉘ ③ の test が作る行は列を足した後の CHECK に合わせて直す（runtime）。
- new schema/input: `pos_source_scans`、`pos_import_sources.first_scan_id`、`source_scan_cursor`。全部実測後の枝を入れる変更は、既存の実測の cursor と資料の `first_scan_id` を変える migration を持つ（D10-25。数量・在庫・売上は変えない）。資料の受領の関数は、読取りの行の ID を受け取る引数が増える（既存の caller は「無し」を渡す）。
- output order: 分類の順は「実測開始前に受領済み」→ D10 → 判定不能。
- optional field behavior: 読取りの行が無い環境と、全部実測後の枝を入れる前の build では、D10 は何も変えない（今の ADR と同じ結果）。SD が固定の disk として見える reader の PC（自動で root を見つけない）でも同じ。
