# Test Design Matrix: MSI の製品名と upgrade code の固定、`identifier` の確定、installer を MSI に絞る（導入の前の関門 4）

Plan Packet: [2026-10-23-msi-fix](../2026-10-23-msi-fix.md)。oracle は [decision-log](../../decision-log.md) D-132 と手順書（[msi-distribution-runbook.md](../../msi-distribution-runbook.md)）の「初回の導入の前に決めること」・「今の事実」・「確かめる項目」。下の期待値は D-132 の値（owner の判断事項 J1〜J3 の答え、repo 外の回答台帳 TD-392）。

## Risk

Risk: R3

## Contracts Under Test

- D-132 (1): `productName` と `app.windows[0].title` が「在庫管理システム」、`bundle.windows.wix.language` が `"ja-JP"`。
- D-132 (2): `bundle.windows.wix.upgradeCode` が、名前を変える前の既定の値（packet の Contract Probe P1）。変えると更新でなく別のアプリとして入る。
- D-132 (3): `identifier` が `com.inventory-system.desktop`。データの folder・WebView の保存の folder・二重起動の防ぎの鍵。値を引く文書・comment に前の名が live で残らない（packet の AC11）。
- D-132 (4): `bundle.targets` が `"msi"`。
- 手順書 M1・M2・M4: MSI だけができ、製品名で 1 つだけ入り、版を上げた MSI と名前を変えた MSI が前の版を置き換え、データの folder の DB が残る。

## Failure Modes

- upgrade code が固定されず（または別の値で）、名前を変えた MSI が前の版と並んで入り、2 つのアプリが同じ DB を開く。
- 誰かが後で upgrade code・`identifier` を変え、更新が別のアプリになる・空の DB で起動する。
- NSIS の setup.exe ができ、配られて別の場所に 2 つ目が入る。
- 日本語の製品名で WiX が失敗する・名が文字化けする。
- 窓の題が雛形の名のまま、起動の直後に出る。
- `identifier` を変えた後も、手順書・設計正本・fixture の README が前の名の folder を案内し、管理者が古い folder を見る。
- 前の名の folder を移さずに新しい名の版を起動し、作業フォルダーの旧 DB が取り込まれる。前の名の folder を消す。

## Mutation の確かめ方

T1〜T4 は Writer が実装の後に、`tauri.conf.json` の該当の値を 1 つずつ変えて `cd src-tauri && cargo test --test bundle_identity_test` を回し、各 1 回 red になることを確かめて戻す（Final Reviewer が独立に 1 つ以上を再実測する）。test の期待値は D-132 の値を直接書き、設定から読んだ値どうしを比べない（同語反復を避ける）。T4 の窓の題は `productName` と同じ値の期待を別に書く。
