## Failure Modes

- F1 同日 2 回の取込みの Z001 を合算する、最新 1 回だけを出す、取込みの並びが逆になる（今の親の読み出しは `imported_at DESC, id DESC`、`sales_repo.rs:1024`）。
- F2 `rolled_back` の親の Z001 行が出る、取消後の再取得で消えない、残りの取込みの番号を振り直さない。
- F3 行の順が `sort_order` と違う、0 の行を隠す、NULL を 0 や「未取得」と出す、`quantity` と `count` を取り違える、個数を 100 倍のまま出す（`quantity_hundredths` を変換せずに wire へ出す）、負の数の符号を落とす・`-¥1,234` の形にする（同じ section の 2 表と食い違う）。
- F4 未取込みの日に日計の見出しや空の表が出る。行の無い取込みで取込み自体が落ち、`summary_imports` の件数が `source_import_count` と食い違う。
- F5 既存の metric・支払集計・部門別集計の合算や warning が変わる、1 回の日の文が変わる、見出しの出どころが付かない。
- F6 bindings を再生成せず、型に `summary_imports` が無いまま UI が別の場所から値を作る。wire の field 列が 34 §19.2 と違う。
- F7 日次 CSV に Z001 のラベルや金額が出る。
- F8 L3 の fixture が今の parser で落ちる、別の精算の混在（`settlement_mismatch`）で止まる、owner が取込みの順を誤って並びが逆になる。
- F9 `{日時}` に秒や `T` が残る、取込み ID や元の順位を `{N}` に使う。

## Mutation-style Adequacy Questions

mutation は対象経路の観測結果を変えるものを選び、既存の適用条件に従って実注入で red を確かめる（Writer が実装後に注入して戻し、結果を PR に書く）。

- If a mock value is changed so it differs from the design-doc expected value: R9 / R11 は mock の `lines` のラベルと値を text で照合し、期待の文字列は 56 UI-09a-D16 の表から転記する。UI が別の値や別の文字列を作れば落ちる。
- If invalidate/refetch changes the value before versus after the operation: R3（repo の取消後）と R11 (2)・(3)。UI の invalidation は既存のまま。
- If a key branch is inverted: `source_import_count >= 2` の分岐を反転すると R9（h4 が出る）と R11（h4 が出ない）が落ちる。
- If a threshold comparison changes: `> 2` に変えると R11 の 2 件の状態 (2) が落ちる。
- If a guard is removed: 親の SELECT（24 §14.21 手順 1）の `status = 'completed'` を外すと、取り消した親が残り R3 の `source_import_count`（期待 2）と `summary_imports` の親 id（期待は残りの 2 親）が落ちる。Z001 の行の query の completed の条件だけを外す mutant は、completed の親を起点に行を振り分ける実装では観測が変わらない（等価）ので kill を主張しない。`official_daily_report === null` の分岐の外へ表を出すと R10 が落ちる。
- If an output field is omitted: `imported_at` を落とすと R7・R11 が落ちる。行の無い親を落とす（join の結果だけで作る）と R4・R13 が落ちる。
- If output order changes: 親の並びを `imported_at DESC` のまま使うと R1・R17 が落ちる。行の `sort_order` を外すと R1 が落ちる。
- If dry-run performs a side effect: 該当なし。
- If a JSON number crosses JavaScript safe integer range: 既存の支払・部門と同じ扱いで本 lane では新しい検査を足さない（Residual）。
- If a state token is round-tripped through browser/client code: 該当なし。
- 個数の変換を外す（`quantity_hundredths` をそのまま `f64` にする）と R7（`Some(1250.0)`）・R17・R9（mock は単位の数なので UI は変わらない。R7 / R17 が kill する）。
- 金額や件数を `Math.abs` で出す、または符号を `¥` の前に置く（`-¥1,200`）と R9 の負の行が落ちる。
- 値の有無を truthiness で判定する（`quantity ?? count` の `??` を `||` にする、`amount ? … : "—"` にする）と、値 0 の行の `0`・`¥0` が `—` になり R9 が落ちる。
- gross / net の加算を取得の並び（ASC）のまま行うと R19 が落ちる（途中の溢れで `QueryFailed`、NULL の場合も `QueryFailed`）。
