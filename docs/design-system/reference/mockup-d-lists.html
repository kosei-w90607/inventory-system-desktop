D の要点（商品一覧） — 統合案 C からの差分だけ。C の枠・検索欄・badge 3 種・primary 1 つ・行高 40px・本文 16px は不変。
  1. 総件数と pagination を上にも: 「238 件 · 1〜50 件目 · 1 / 5 ページ」を table 直上に置き、下の pager は従来どおり。件数は 16px 太字（何件あるかが最初に目に入る）。
  2. table header を sticky: スクロールしても列名が消えない。header 背景 + 2px の区切りで本文と混ざらない。
  3. 識別列を見失わない: 商品コード（太字・等幅数字）と商品名を左に固定し、横スクロール時に右端へ影。hover は識別列まで含めて全幅。
  4. コントラスト（実測、WCAG 2.x 相対輝度）: 構造線（行区切り・表枠）#e7e5e4 → #cdc8c4 = 白地 1.26:1 → 1.66:1（装飾線は 3:1 の対象外、見やすさのため一段濃く）。操作枠（ボタン・入力・select・seg・badge 枠）#e7e5e4 → #8a8480 = 白地 3.69:1 / 地色 #fafaf9 上 3.53:1（非テキスト UI 部品の AA 3:1 を満たす）。文字色は変えない（本文 16.7:1、現在行 #fff8e6 上の本文 16.5:1。本 mockup の補助文字 #57534e は現在行上で 7.2:1 だが、これは統合案 C mockup のデモ配色で、実 token `--muted-foreground` #78716c では 4.53:1〈AA〉）。
  5. 低視力（緑内障）前提: 件数・操作・識別列を左上に集め、視野の端だけに置く情報を作らない。focus ring 2px + offset は C と同じ。

D の要点（在庫照会） — C の状態 badge 3 点セット（icon + 日本語 + 色）と開いた行の詳細は不変。
  1. 開いている行 = 現在の行: 左バー + 淡背景で、詳細行がどの商品のものか一目で結び付く。
  2. 件数 + pager を上に: 1,204 件の一覧で「いま 1〜50 件目」が最初に見える。
  3. sticky header + 識別列固定: 他の一覧と同じ器（shared `DataTable` 化の候補）。
位置付け: 正本は 04-backbone.md（原則 1〜12）。D は 2026-08-23 の Windows native L3（UI-14、実利用者に緑内障）で得た所見 5 点（総件数と pagination を上部にも / table header の sticky 化 / 長い一覧で商品識別列を見失わない / 枠線・背景・操作領域のコントラスト強化 / 低視力を前提にした再評価）を、C の token・器・badge を変えずに上乗せした提案。採用されれば 04-backbone に原則 13〜16 として追記し、02-component-catalog に一覧の器（toolbar + sticky header + 識別列固定 + 上下 pager）を shared pattern として登録する。数値（線 #cdc8c4 / 操作枠 #8a8480 / 現在行 #fff8e6）は本 mockup の提案値で、実測コントラスト表（Lane 0-c）で確定する。
D の対象外: サイドバー・PageHeader・「商品登録」などのボタン・検索欄の見た目は統合案 C の mockup の描き方をそのまま使っており、D の提案ではない。実装は現行アプリの shadcn 部品の見え方を土台にし、C / D と現仕様のどちらを採るかは Lane 1 packet で項目ごとに決める（owner 所感 2026-08-23: 現仕様の方が良い箇所がある）。
v1 → v2: 識別列 2 列目の固定位置を固定 rem から 1 列目の実幅計測（JS）に変更（v1 で隙間が出た不具合の修正。実装でも shared component 側で計測する）。v3 → v4: 固定列右端の影を「横スクロール中だけ」出す（`.scroll.sx`）ようにし、header 側の影が共通の下線（`0 1px 0`）を消していた不具合を修正（owner 所見 2026-08-23「列名と 1 行目の間で 2 列目だけ浮いて見える」）。実装でも固定列の影は scrollLeft > 0 のときのみ付け、sticky header の下線と合成する。
