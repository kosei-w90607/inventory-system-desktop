D の要点（棚卸し） — 一覧画面と同じ器を使う最有力候補。
  1. 差異列は色分けしない（77-ui とは異なり 73-ui 契約: 「色分けなし、符号付き数値のプレーンテキストのみ」）。D でも badge 化せず、`+2` / `-1` のプレーン数値のまま。
  2. 上部に進捗: 「入力済み 128/238」+ Progress を toolbar の上、絞り込みより先に置く（棚卸しは残数の把握が主目的）。
  3. 識別列固定 + sticky header + 上下 pager: 一括価格改定・商品一覧と同じ器。238 件級で最も効く。
  4. 現在の行: 検索/スキャンで解決した直後の行に左バー + 淡背景（入力中 badge は付けず、数量入力欄への自動フォーカスで示す — HID 連続スキャン運用のため行クリックで開く一覧画面の badge とは性質が異なる）。
  5. 確定ダイアログは D の一覧改善と無関係（既存 73-ui-D4/D10 契約のまま）。ここでは title 分岐 2 種を並べて見比べられるようにしただけ。
未決: 進捗 Progress の色（primary 琥珀を使用、doc は色を規定しない）。doc に無く追加しなかったもの: PLU 対象外・除外品の列や filter — 73-ui-stocktake.md に PLU 状態列の記載はなく、棚卸しは PLU 状態を問わず全商品が対象のため追加していない。
位置付け: 正本は 04-backbone.md + 各 function-design（62/64/73-ui）。本 mockup は 2026-08-23 の L3 所見 5 点を forms 系画面へどこまで適用するかの方向確認用の提案で、実装の正本ではない。棚卸しのように大量行の一覧を持つ画面は list 系（`mockup-d-lists.html`）と同じ器を適用し、手動販売・廃棄のように数行の伝票入力が中心の画面は操作枠のコントラスト強化のみに留めている。文言・数値はダミー、doc に無い文言は各 note の「未決」に列挙した。
