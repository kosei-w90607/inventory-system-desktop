# 日報・月次の画面の導入前受入の手順（開発用の Windows、管理者向け）

> **対象**: アプリを管理する人。店の利用者の操作にしない。店の PC では行わない。
> **いつ使うか**: 店へ入れる版の MSI（[initial-load-runbook.md](initial-load-runbook.md) の流れ 2 と同じ版）ができた後、店の PC への初期投入（同じ手順書の流れ 3）の前に。完了の画面を離れた後の取消の入口の lane（以下 A）と、月次の画面に月の中の取り込んだ日を出す lane（以下 B）が merge された版で行う（[Plans](Plans.md#導入の前の関門) の導入の前の関門の 12）。
> **引く正本**: 受入の項目・合格基準・判定は [56](function-design/56-ui-daily-sales.md) UI-09a-D13 と [57](function-design/57-ui-monthly-sales.md) UI-09b-D9 の受入の段、SD の一覧と「場所を選ぶ」は [55](function-design/55-ui-csv-import.md) UI-07-D15、窓（今日から 30 日前まで）は [37](function-design/37-biz-daily-report-import-service.md) §37.9、写しの folder の選び方（`resolve_register_sd_root`）と取込みのときの写しは [29](function-design/29-io-daily-report-parser.md) IO-09・IO-10、復元は [68](function-design/68-ui-backup-restore.md) §68.4、backup を SD の上に書かないことと別の PC に店のデータを置く間の扱いは [71](function-design/71-mnt-backup.md) MNT-01-D10・§71.13。owner の決定は repo 外の回答台帳 TD-570（関門 12）・TD-578（場と時期・店の事実・前提の lane・FAIL の扱い）・TD-580（綴りの紙の運び方）。本書は正本の契約を引いて手順を並べ、正本に無い所は安全側に倒した管理者の判断を足す（写しの置き場、比べる日の選び方、同じ日に予行演習と続けるときの順）。食い違えば正本が正しい。
> **この受入が置き換えないもの**: 日報の紙と月の売上の紙のどちらも置き換えない（57 UI-09b-D9）。日報の紙の切替えの前の照合（56 UI-09a-D19 の (2)、TD-560）は運用開始の後に別に行う。

## 店のデータの置き場と渡し方

レジの SD の写し（`XZ`・`XZ_BKUP` の全 file）と、受入で作る data folder（取り込んだ記録の DB・アプリが残す SD の写し〈IO-10〉・backup）と WebView の保存の folder は、店の実データとして扱う。

- 置いてよい所は 2 つだけ。管理者の USB メモリの、root でない日付の付いた folder（その USB メモリは店の PC と開発用の Windows でだけ開き、受入の間は管理者が手元に保管する）と、開発用の Windows の、drive の直下でない日付の付いた folder。
- 開発用の Windows の folder は、repo の checkout の外（ignored の `.local/` も不可）で、cloud の同期の外に置く。置く前に、その folder が `%OneDrive%` の下でないことを確かめる（デスクトップ・ドキュメントは同期の下でありうる）。
- drive の直下・USB メモリの root に `CASIO` を置かない。開発用の Windows では自動の探索がその USB メモリを SD と見なし（29 IO-09 の手順 1）、店の PC で SD と一緒に差すと SD が 2 枚と数えられ（37 §37.9 の手順 1）、その drive への backup も止まる（71 MNT-01-D10）。
- AI の agent（Claude・Codex）への発注・報告・handoff に、写し・受入の data folder・backup の path や店の値を書かない。agent に読ませる作業をしない（agent は開発用の Windows の file を読めるので、場所でなく渡し方で守る）。owner への報告は TD 番号で引く。
- 綴りの紙は、紙かそのコピーを店から借りて開発用の Windows の前で並べ、返す（TD-580）。写真は撮らない。
- repo に入れないもの: 店の売上の値（金額・件数）、SD の file と写し、綴りの紙・そのコピー・画面の写し、店の file 名の実例。本書は金額を書かず、file 名は形（`Z001_…` の類）だけで書く。

## 写しを取る（訪店の時）

1. 店の PC で、レジの SD の `CASIO` の folder を丸ごと（中の `SR500_550_4000` の `XZ` と `XZ_BKUP` ごと）、管理者の USB メモリの root でない日付の付いた folder の中へ写し、`<日付の folder>\CASIO\SR500_550_4000\XZ` の形にする。`SR500_550_4000` や `XZ` だけを写さない（`SR500_550_4000` を選ぶと親の名が `CASIO` であることを確かめるので〈29 IO-09 の手順 3 `resolve_register_sd_root`〉、「場所を選ぶ」で止まる）。
2. SD に書かない・消さない・名前を変えない（写すだけ）。写し終えた SD はすぐにレジへ戻す。
3. 比べる日の綴りの紙を、紙かそのコピーで店から借りる（写真は撮らない）。比べる日は写しを取った日に近い日にする（窓は開発用の Windows の今日から 30 日前までなので、古い日ほど早く一覧から落ちる）。
4. 管理者の記録に、写した日と綴りの紙を借りた日を書く。

## 準備（開発用の Windows）

1. 写しを USB メモリから開発用の Windows の置き場（上の「店のデータの置き場と渡し方」）へ、同じ形（`<日付の folder>\CASIO\SR500_550_4000\XZ`）で写す。
2. [msi-distribution-runbook.md](msi-distribution-runbook.md) の「予行演習の準備と片付け」（[確かめる項目](msi-distribution-runbook.md#確かめる項目) の節）の「始める前に」のとおり、開発の data folder（`%APPDATA%` と `%LOCALAPPDATA%` の `com.inventory-system.desktop`）を退避する。開発に使っている data folder（開発の試験のデータ・合成の日報が入ったもの）の上で受入を走らせない（取込み済みの状態と窓が変わり、合否が読めない）。
3. 店へ入れる版の MSI を入れ、最初の起動の前にショートカットの作業フォルダーに `inventory.db` が無いことを確かめてから（同じ節の 2 つ目の段）起動する。商品と日報の取込みが 0 件の空の DB であることを確かめる。1 件でもあれば止める。
4. 写しを取った日から 30 日以内に下の手順を走らせる（窓は開発用の Windows の今日から 30 日前まで。古い日は一覧に出ない）。窓の外に落ちた日は受入で読まない。予備の経路「ファイルを選んで取り込む」（55 UI-07-D16）は受入で使わない。比べる日が窓から落ちたら、次の訪店で写しを取り直す。
5. 同じ日に初期投入の流れ 2（予行演習）と続けて行うときは、先に行う方の「終わった後」（msi-distribution-runbook.md の同じ節）まで済ませてから、後に行う方の「始める前に」から始める（流れ 2 の後の DB は商品が入っていて空でない）。受入の data folder と流れ 2 の folder は別の名で保全し、混ぜない。

## 手順

取込みと復元は、準備で作った受入の data folder の中だけで行う。手順 6 の backup の作成から復元までは同じ日のうちに行う（日をまたぐと起動の時の保持日数の削除で backup が消えうる。71 MNT-01-D3、初期投入の流れ 2 と同じ注意）。

1. **一覧を読み、日を選ぶ。** `売上データ取込み` の画面の `日報取込み` の tab で `SD から読む` を押す。SD が見つからないので `場所を選ぶ` が出る。それを押し、写しの `<日付の folder>\CASIO` か `<日付の folder>\CASIO\SR500_550_4000` を選ぶ。一覧の日の範囲と件数を管理者の記録に書く（O2 (iii)）。一覧から、同じ月の窓の中の `取り込めます` の日を 3 日以上選んでおく: 比べる日（借りた綴りの紙のある日）、手順 5 の日、手順 4 と手順 6 に使う取り込まずに残す日。同じ日の 2 回の精算は 1 日と数える。3 日に足りない月は比べる月にしない（足りる月が無ければ次の訪店で写しを取り直す）。
2. **比べる日を取り込む。** 比べる日（2 回以上精算した日も比べるならその日も）を 1 日ずつ、一覧の行の `確認する` → `取込み内容` を見て `取り込む`。2 回以上精算した日の 2 つめの束では `同じ日の取込みがあります` が出るので、同じ日の別の精算であることを確かめて進む。次の日は完了の画面の `SD の一覧へ戻る` から選ぶ。
3. **綴りの紙と並べる。** `日次売上` の画面で比べる日を開き、`レジ日報（公式）` の `日計（Z001）`・`支払集計（Z002）`・`部門別集計（Z005）` の 3 つの表を、借りた綴りの紙（かそのコピー）のその日の同じ帳票の枠と、行ごとに並べる。1 回の日で比べ、2 回以上の日は並べて違いを控える（合否に数えない。O2 (i)）。
4. **取り込んでいない日。** `日次売上` の画面で `前日`・`翌日`・日付の入力で、手順 1 で残した日へ着き、`この日付のレジ日報は未取込みです。` が出ることを見る（手順 6 の後に行ってもよい。復元でその日は未取込みに戻る）。
5. **取り消して取り込み直す。** 手順 1 で選んだ手順 5 の日を `確認する` → `取込み内容` の `支払集計`・`部門別集計` と `総売上`・`純売上` を見て `取り込む` → `日報取込み完了` の `総売上`・`純売上` を見る → 完了の画面のまま `取り消す`（確認の dialog の `取り消す`）→ `日報取込みを取り消しました` が出る → `日次売上` でその日に `この日付のレジ日報は未取込みです。` が出る → `日報取込み` の tab で `SD から読む` → `場所を選ぶ` から同じ束を取り込み直す。取り込み直した後、`日次売上` の画面のその日の値が、取り込み直す前の確認の画面（`支払集計`・`部門別集計`）と完了の画面（`総売上`・`純売上`）の値と同じであることを見る（同じ束なので最初の取込みの値と同じ）。取り込み直した日は取込み済みになり、手順 7 の和に入る。手順 4 と手順 6 に使う取り込まずに残す日には触れない。
6. **backup/restore 後の再現。** 受入の data folder の中だけで、`バックアップ・復元` の画面の `手動バックアップ` の `今すぐバックアップを作成` で backup を作る → 手順 1 で残した比べる月の日の束を 1 つ取り込み、その日の値が変わる（未取込みの note が消えて表が出る）のを見る → `バックアップ・復元` の一覧からこの手順で作った backup を選び、`この控えに戻す` → `復元の確認へ進む` → 確認の dialog で戻す（同じ日のうちに。戻す前の自動の backup は残る、68 §68.4）→ 日次・月次の値が backup を作った時の値と同じことを、金額を書かずに次で見る: 比べた日の日次は借りた綴りの紙と同じ、後で取り込んだ日は `この日付のレジ日報は未取込みです。` に戻る、月次の `公式部門集計（レジ日報由来）` はその月に取り込んだ日（後で取り込んだ日を除く）の日次の `部門別集計（Z005）` の和と同じ。取消を使わないので A に依らない。
7. **月次の値。** `月次売上` の画面（`日次`・`月次` の切替えと `前月`・`翌月`・月の入力）で比べる月を開き、`公式部門集計（レジ日報由来）` の部門ごとの額が、その月に取り込んだ日（比べる日と手順 5 の日の 2 日以上）の日次の `部門別集計（Z005）` の和と同じことを見る。取り込んだ日の無い月で `この月のレジ日報は未取込みです。` が出ることを見る。
8. **記録と判定。** 下の合格基準の表の行ごとに PASS/FAIL を管理者の記録に書き、下の「判定」の規則で全体を決める。

## 判定

- 「前提の lane の後に足す」のままの行が残る版、または A・B の lane が merge される前の版では、全体の判定は未了で、初期投入の流れ 3 へ進まない（他の項目が全部 PASS でも）。
- 全体の合格は、「前提の lane の後に足す」のままの行が無く、行う行が全部 PASS のときだけ。月の帳票との照合の行は「行わない（理由）」と書いた間は合否に数えない。
- FAIL の扱い（O5）: 1 つでも FAIL があれば運用を始めない（初期投入の流れ 3 へ進まない）。合わなかった項目と行の名称を控え、直す lane を起こす。店の DB には受入の記録が無いので、店の側で戻す操作は無い。直した版で準備から受入をやり直す。
- 受入の data folder が途中で壊れたときは、アプリを止めて folder を別名で保全し、準備からやり直す（写しは USB メモリと開発用の Windows の folder に残る）。

## 終わった後

1. アプリを止め、msi-distribution-runbook.md の「予行演習の準備と片付け」の「終わった後」の順で開発の data folder を戻す。その手順の (2) で、受入の data folder（`%APPDATA%\com.inventory-system.desktop`。取り込んだ記録・SD の写し〈IO-10〉・backup を持つ）と WebView の保存の `%LOCALAPPDATA%\com.inventory-system.desktop` は消さずに別名で残る。
2. この 2 つの別名の folder・USB メモリの写し・開発用の Windows の写しは店のデータで、FAIL の直しの再受入まで保ち、消す時期は owner が決める（71 §71.13 の別の PC に店のデータを置く間の扱いと同じ。開発用の Windows へ写して確かめた後に USB メモリの写しを残すかも、この判断に含める）。
3. 借りた綴りの紙（かそのコピー）は店へ返し、返した日を管理者の記録に書く（TD-580）。

repo の外に書く。金額を書かない。

- 比べた日（比べる日・手順 5 の日・残した日）
- 項目ごとの PASS/FAIL（「行わない（理由）」を含む）と全体の判定
- 合わなかった項目と行の名称
